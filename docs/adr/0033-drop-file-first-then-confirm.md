# ADR-0033: 파일을 먼저 놓고 값을 확인한다

- 상태: 수락됨
- 날짜: 2026-09-09

## 맥락

[ADR-0031](0031-register-and-first-upload-in-one-screen.md) 로 등록과 첫 버전
업로드를 한 화면에 합쳤지만, 그 화면은 여전히 **긴 폼 위에 파일 칸이 하나 얹힌**
모양이었습니다. 파일을 고르기 전에는 채울 수 없는 칸이 눈앞에 다 펼쳐져 있고,
파일을 고르면 그중 다섯 개가 저절로 바뀝니다.

순서가 뒤집혀 있었습니다. **파일이 값을 정하는데 폼이 먼저 있었습니다.**

[ADR-0032](0032-accept-disk-images.md) 로 dmg 를 받기 시작한 뒤 문제가 더 커졌습니다.
같은 화면인데 고른 파일에 따라 동작이 갈립니다. zip 이면 다섯 칸이 채워지고 dmg 면
아무것도 안 채워집니다. 브라우저가 디스크 이미지를 열 수 없기 때문인데
([ADR-0030](0030-read-bundle-info-in-browser.md)), 화면은 그 차이를 설명문 한 줄로만
알렸습니다.

## 결정

**두 단계로 나눕니다.**

```
1단계  파일을 끌어다 놓는다 (다른 입력 없음)
2단계  값을 확인하고 모자란 것을 채운다
```

1단계에는 파일 놓는 자리와 "파일 없이 앱만 등록" 버튼뿐입니다. 채울 수 없는 칸을
보여주지 않습니다.

2단계는 1단계에서 무엇을 읽었는지에 따라 다릅니다.

| 올린 것 | 2단계에서 보이는 것 | 사람이 적을 것 |
| --- | --- | --- |
| zip | 읽은 다섯 값 + 첫 버전 칸 | 없음 (소개·분류는 선택) |
| dmg | 경고 + 앱 정보 칸. **첫 버전 칸은 감춤** | 번들 ID |
| 없음 | 앱 정보 칸만 | 번들 ID, 이름 |

### dmg 는 버전을 묻지 않습니다

사람이 짐작해 적을 값이 아닙니다. 대신 **임시값으로 만들고 워커가 고칩니다.**

`versions.short_version` 과 `build_number` 가 둘 다 `not null` 이라 비워둘 수
없습니다. 그래서 `0.0.0` / 빌드 `1` 로 만들어 올리고, 워커가 서명 직전에 번들에서
읽은 값을 보고하면 서버가 `short_version` 과 `minimum_os_version` 을 고칩니다.

그 사이 버전은 `업로드됨` 이거나 `서명 중` 입니다. **아무도 설치할 수 없고 출시되지도
않은 상태**라 틀린 값이 밖으로 나가지 않습니다.

**빌드 번호는 고치지 않습니다.** 앱 안에서 겹칠 수 없는 값이라(unique) 바꾸면 다른
버전과 충돌할 수 있고, 그 충돌을 서버가 풀 방법이 없습니다. 다르면 로그에만 남깁니다.

### 적어야 하는 칸만 드러냅니다

dmg 로 올릴 때 실제로 적어야 하는 것은 번들 ID 하나입니다. 그런데 그 아래로 이름·
소개·설명·분류가 펼쳐져 있으면 **다 적어야 하는 것처럼 보입니다.** 비어 있는 칸이
넷이면 무엇을 더 해야 하는지 찾게 됩니다.

이름과 설명은 `<details>` 로 접어둡니다. 이름은 zip 이면 번들에서, dmg 면 파일
이름에서 채워두고, 나머지 셋은 원래 선택입니다. 전부 나중에 고칠 수 있습니다.

접는 규칙은 하나 더 있습니다. **이름이 비어 있으면 반드시 펼칩니다.** `required` 인
칸이 닫힌 `<details>` 안에 있으면 브라우저가 "invalid form control is not focusable"
로 제출을 막는데, 화면에는 아무 표시도 나지 않습니다. 사람은 등록 버튼이 죽은 줄
압니다.

zip 은 읽은 값을 보여주는 것이 이 단계의 목적이라 펼칩니다.

### 고르기 전에 zip 을 권합니다

1단계에 안내를 둡니다. 고른 뒤에 "zip 이 나았다" 고 말하면 늦습니다. zip 이면 적을
것이 없고 dmg 면 번들 ID 를 직접 적어야 한다는 차이와, 빌드 도구가 zip 을 함께
뱉게 하는 방법(electron-builder 의 `target`, Xcode 내보내기 뒤 `ditto`)까지 적습니다.

### 번들 ID 는 사람이 적습니다

dmg 에서 이것만 묻는 이유는 **앱을 만들 수 없기 때문**입니다. `apps.bundle_id` 는
`not null` 이고 나중에 바꿀 수도 없습니다(`UpdateAppRequest` 에 없습니다). 설치된 앱의
정체성이라 바꾸면 다른 앱이 됩니다([ADR-0005](0005-bundle-id-and-app-id-policy.md)).

틀리면 어떻게 되는지 화면에 적습니다.

> dmg 는 브라우저가 열 수 없어 값을 미리 읽지 못합니다. 번들 ID 를 정확히
> 적어주세요. 실제 앱의 번들 ID 와 다르거나 아래 규칙에 맞지 않으면 **파일을 다
> 올린 뒤 서명 단계에서 실패합니다.**

실제로 그렇게 동작합니다. 워커가 서명 전에 대조해서 다르면 멈춥니다
([ADR-0029](0029-verify-bundle-identifier-before-signing.md)).

### 워커의 값이 진실입니다

브라우저 자동 채우기는 사람이 적은 값을 덮지 않습니다(ADR-0030). 여기는 반대로
**덮습니다.** 자리가 다릅니다.

- 브라우저: 아직 올리기 전이다. 사람이 화면에서 고칠 수 있다
- 워커 보고: 서명·공증까지 끝났다. 실제로 배포되는 바이너리에서 읽은 값이다

배포되는 것이 `1.2.4` 인데 목록에 `1.2.3` 으로 적혀 있으면 그게 더 나쁩니다. 스토어
앱은 번들의 값으로 설치 여부를 판단하므로 어긋난 채 두면 업데이트 표시가 틀립니다.

## 대안과 기각 사유

**접수(intake) 구조를 만든다** — 파일만 먼저 떨궈두고 워커가 집어 번들 ID 까지 읽어
보고하면 그때 앱과 버전을 만드는 방법입니다. dmg 도 사람이 한 칸도 적지 않게 됩니다.
가장 깔끔한 그림이었습니다.

기각한 이유는 셋입니다. 첫째, **워커가 처리할 때까지 앱이 존재하지 않습니다.** 지금은
등록이 즉시인데 워커가 꺼져 있으면 몇 분에서 몇 시간을 기다립니다. 둘째, 번들 ID 가
프리픽스 정책을 어기거나 이미 등록돼 있으면 **수백 MB 를 다 올린 뒤에** 알게 됩니다.
셋째, 앱도 버전도 아닌 새 테이블과 새 상태 흐름이 필요합니다. 지금 얻는 것은 dmg 를
올릴 때 한 칸 덜 적는 것뿐입니다.

**dmg 도 버전을 묻는다** — 임시값이 없어서 흐름이 단순합니다. 워커가 실패하면 `0.0.0`
버전이 남는 일도 없습니다. 그러나 올리는 사람은 그 값을 이미 번들 안에 적어뒀습니다.
같은 것을 또 적게 하는 것이고, 손으로 옮기면 틀립니다. 틀린 채로 출시되면 스토어
앱의 업데이트 판단이 어긋납니다.

**한 화면에 두고 파일 칸만 위로 올린다** — 가장 작은 변경입니다. 그러나 채울 수 없는
칸이 여전히 눈앞에 펼쳐져 있고, zip 과 dmg 의 차이를 설명문으로만 알리는 문제도
그대로 남습니다.

**dmg 를 아예 안 받는다** — ADR-0032 를 되돌리는 것입니다. 그러면 이 ADR 이 필요
없어집니다. 그러나 빌드 도구가 뱉는 것이 dmg 라 사람이 매번 다시 압축해야 합니다.

## 결과

**좋은 점**

- 파일이 값을 정하는 순서대로 화면이 흐릅니다. 채울 수 없는 칸을 미리 보여주지
  않습니다
- dmg 로 올릴 때 사람이 적는 것이 한 칸입니다. 버전은 워커가 채웁니다
- zip 과 dmg 의 차이가 설명문이 아니라 **화면 구성으로** 드러납니다. dmg 면 버전 칸이
  아예 없고 경고가 뜹니다
- 틀렸을 때 어디서 실패하는지 미리 말합니다

**나쁜 점**

- **워커가 실패하면 `0.0.0` 버전이 남습니다.** 그 버전은 서명도 안 됐으니 쓸 수
  없지만, 목록에 `0.0.0` 으로 보이는 것은 헷갈립니다. 방치된 `draft` 청소
  ([ADR-0019](0019-abandoned-draft-cleanup.md))는 `draft` 만 지우고 이것은 `failed`
  라 남습니다
- **워커가 값을 덮어씁니다.** ADR-0030 과 반대 규칙이 한 레포에 둘 생겼습니다.
  자리가 다르다는 것을 위에 적었지만, 다음에 고치는 사람은 "어느 쪽이 맞나" 를 한 번
  물을 것입니다
- 화면이 두 단계라 뒤로 가기가 필요해졌습니다. 브라우저의 뒤로 가기가 아니라 화면 안의
  버튼이라, 브라우저 뒤로 가기를 누르면 앱 목록으로 나갑니다
- **1단계는 스크립트가 없으면 아예 없습니다.** 그때는 2단계 폼이 드러나 있고 앱만
  등록됩니다. ADR-0031 에 적은 대가가 그대로 이어집니다
- `dropzone` 이 `<input type=file>` 을 투명하게 덮는 구조라, 상자 안의 글자를 마우스로
  선택할 수 없습니다
