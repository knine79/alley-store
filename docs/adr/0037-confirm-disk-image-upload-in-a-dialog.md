# ADR-0037: dmg 업로드 확인을 `<dialog>` 로 받는다

- 상태: 수락됨
- 날짜: 2026-09-10

## 맥락

[ADR-0034](0034-worker-decides-bundle-id-for-disk-images.md) 에서 dmg 는 아무것도
묻지 않고 올리기로 했습니다. 대신 올리기 직전에 한 번 확인받기로 했고, 그때는
브라우저 `confirm` 을 골랐습니다. 이유는 이랬습니다.

> 투박하지만 되돌리기 어려운 일 앞에서 멈춰 세우는 것이 목적이고, 직접 만들면 초점
> 가두기와 Esc 처리를 새로 만들어야 하는데 이 콘솔에 그런 장치가 없습니다.

**그 전제가 틀렸습니다.** 직접 만들 필요가 없습니다. `<dialog>` 가 초점 가두기와
Esc, 배경 가림을 다 해줍니다. 새로 만들 것은 없고 쓰기만 하면 됩니다.

그리고 `confirm` 에는 실제 대가가 있었습니다. 서식이 없어서 접두어를 `code` 로
구분해 보여줄 수 없고, 버튼 이름이 "확인/취소" 로 고정이라 무엇을 하는 버튼인지
사람이 문장에서 유추해야 합니다. 문구도 스크립트가 조립해서, 서버가 아는 접두어
정책과 두 군데로 나뉘어 있었습니다.

## 결정

네이티브 `<dialog>` 로 띄우고, 버튼은 **취소**와 **업로드** 둘입니다. 문구는
템플릿에 있고 접두어는 서버가 렌더링합니다.

```
[업로드] 누름 → 팝업
                ├ 취소 / Esc → 아무 일도 없음. 고른 파일은 그대로
                └ 업로드     → 실제 업로드 시작
```

취소를 먼저 둡니다. 폼의 첫 제출 버튼이 Enter 의 기본값이라, 무심코 Enter 를 눌러도
올라가지 않습니다.

### dmg 는 확인 화면을 거치지 않습니다

번들 ID 도 버전도 entitlements 도 묻지 않게 되면서([ADR-0034](0034-worker-decides-bundle-id-for-disk-images.md),
[ADR-0036](0036-ask-for-entitlements-only-when-needed.md)), 2단계에 남은 것이
한 문장과 버튼 둘뿐이었습니다. **적을 것이 없는 화면을 한 번 거치게 하고 그다음에
팝업을 띄우고 있었습니다.**

그래서 dmg 는 파일을 놓는 즉시 팝업입니다. 1단계에 머물기 때문에 취소하면 다른
파일을 바로 고를 수 있습니다. 취소할 때 고른 것을 지웁니다. 1단계에는 "다음" 이
없어서, 남겨두면 같은 파일을 다시 고르기 전에는 아무 데도 갈 수 없습니다.

진행률 표시는 두 단계 밖으로 옮겼습니다. 2단계 안에 두면 dmg 를 올리는 동안 아무
표시도 나오지 않습니다. 올리는 중에는 드롭존도 잠급니다. 그때 다른 파일을 놓으면
무엇이 올라가는 중인지 알 수 없게 됩니다.

zip 은 그대로 2단계로 갑니다. 읽어낸 값을 보여주고 고치게 하는 것이 그 화면의
일이고, 그건 여전히 할 일이 있습니다.

### `close` 이벤트를 믿지 않습니다

**이것이 이 ADR 에서 가장 중요한 대목입니다.**

`<dialog method="dialog">` 는 누른 버튼의 `value` 를 `returnValue` 에 담고 `close`
이벤트를 냅니다 - 명세로는 그렇습니다. 그렇게 만들었고, 서버 렌더링 테스트도 전부
통과했습니다. **그런데 브라우저에서는 업로드를 눌러도 아무 일이 없었습니다.**

Chrome 152 헤드리스에서 재보니 `close` 가 아예 오지 않습니다. `dialog.close()` 로
직접 닫아도 마찬가지입니다. `returnValue` 는 제대로 들어가는데 이벤트만 없습니다.

| 무엇으로 닫나 | `close` | `cancel` | 폼 `submit` |
| --- | --- | --- | --- |
| 버튼 클릭 | 안 옴 | - | 옴 |
| `dialog.close("x")` | 안 옴 | - | - |
| Esc | 안 옴 | 옴 | - |

그래서 확실히 오는 둘에 겁니다. 버튼은 폼의 `submit`, Esc 는 `cancel` 입니다.
`close` 도 함께 달아두되 셋 중 먼저 오는 것 하나만 씁니다. 어느 버튼인지 알 수
없으면 **올리지 않습니다.** 되돌릴 수 없는 쪽으로 기울지 않습니다.

### 문구는 템플릿에 둡니다

접두어 정책은 서버 설정입니다. 스크립트가 문장을 조립하면 정책이 바뀔 때 두 군데를
고쳐야 하고, 한쪽만 고치면 화면과 실제가 어긋납니다. `confirm` 으로 떨어지는
경우에도 팝업 본문을 읽어서 같은 말을 합니다.

## 대안과 기각 사유

**`confirm` 을 그대로 둔다** — 코드가 가장 적고, 이번에 만난 `close` 이벤트 문제도
없습니다. 그러나 서식이 없어 접두어를 강조할 수 없고 버튼 이름을 정할 수 없습니다.
요청받은 것이 정확히 그 둘입니다.

**직접 만든 오버레이(`div` + CSS)** — 모양을 마음대로 할 수 있습니다. 그러나
초점 가두기, Esc, 배경 스크롤 잠금, `inert` 처리를 전부 손으로 만들어야 합니다.
`<dialog>` 가 공짜로 주는 것을 다시 만드는 일입니다.

**확인을 아예 없앤다** — 화면이 가장 단순합니다. 그러나 몇백 MB 를 보낸 뒤에
"규칙에 안 맞아 실패했다" 를 처음 듣게 됩니다. 그것을 피하려고 넣은 확인입니다.

## 결과

**좋은 점**

- 접두어를 `code` 로 구분해 보여줍니다. `confirm` 에서는 문장에 섞여 있었습니다
- 버튼이 **취소 / 업로드** 라서 무엇을 하는지 읽으면 압니다
- 문구가 서버 템플릿 한 곳에 있습니다. 정책과 화면이 어긋나지 않습니다
- 초점 가두기·Esc·배경 가림은 여전히 브라우저가 합니다. 만든 것이 없습니다
- 2단계 화면에서 인라인 경고가 빠졌습니다. 같은 말을 두 번 하지 않습니다
- **dmg 는 화면이 하나 줄었습니다.** 놓으면 바로 물어보고, 답하면 바로 올라갑니다

**나쁜 점**

- **`close` 를 못 믿는 코드가 남았습니다.** 리스너를 셋 달고 먼저 오는 것을 씁니다.
  명세대로면 하나면 될 일이라, 사정을 모르는 사람이 보면 과해 보입니다. 주석과 이
  ADR 이 유일한 설명입니다
- **브라우저 없이는 검증되지 않습니다.** 서버 렌더링 테스트는 팝업이 잘 그려졌다는
  것까지만 압니다. 눌렀을 때 무슨 일이 일어나는지는 실제 Chrome 으로 몰아봐야 알고,
  그 하네스는 레포에 없습니다. **이번 버그가 정확히 그 틈에서 나왔습니다**
- `confirm` 폴백이 남아 있어 같은 문구를 두 가지 방법으로 보여줍니다. 폴백 쪽은
  본문을 긁어 만들어서 서식이 사라집니다
- `<dialog>` 를 모르는 브라우저(Safari 15.3 이하)에서는 폴백으로 떨어집니다
- **dmg 와 zip 이 서로 다른 길을 갑니다.** 하나는 1단계에서 끝나고 하나는 2단계로
  갑니다. 화면 흐름이 파일 형식에 따라 갈리는 것은 읽기 어렵고, `go()` 안에 그
  분기가 들어갔습니다
- **취소하면 고른 파일이 사라집니다.** 팝업을 잘못 닫은 사람은 다시 골라야 합니다.
  1단계에 "다음" 을 두면 안 지워도 되지만, 그러면 zip 에는 없는 버튼이 하나 생깁니다
