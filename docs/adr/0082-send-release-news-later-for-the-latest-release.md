# ADR-0082: 알리지 않고 출시한 가장 최근 출시본은 나중에 소식을 보낼 수 있다

- 상태: 수락됨
- 날짜: 2026-11-03

## 맥락

ADR-0075 는 알릴지를 출시하는 순간에만 고르게 했습니다. 그 순간을 놓치면 되돌릴 길이
없었습니다 (이슈 #81).

- 채널이 없을 때 출시 팝업의 "채널 등록하러 가기" 는 출시하지 않고 채널 칸으로 내려가기만
  했습니다. 채널을 넣으면 화면이 다시 그려지고 끝이라, 출시하던 버전을 다시 찾아 눌러야 했습니다
- "알리지 않고 출시" 를 고른 뒤에는 그 버전의 소식을 보낼 수 없었습니다. 철회했다 다시
  출시하는 것뿐이었고, 그동안 받으려던 사람에게 앱이 사라집니다. 채널을 늦게 등록한
  앱은 첫 출시 소식("🎉 ... 출시되었습니다")을 영영 보내지 못했습니다

## 결정

**알리지 않고 출시한 버전 중 가장 최근 출시본 하나에만 "출시 소식 보내기" 를 둡니다.
누르면 확인 팝업을 거쳐 출시할 때와 같은 글을 보냅니다. 웹 콘솔에만 엽니다.**

- 가장 최근 출시본은 빌드 번호가 가장 높은 `released` 버전입니다. 그 버전이 이미 알렸으면
  어디에도 단추가 없습니다
- 보내는 일은 `ReleaseNews.announce` 를 그대로 씁니다. 한 버전 한 번(`announced_at`),
  한 곳에도 못 보내면 내려놓기, 채널별 실패 기록이 출시할 때와 같습니다. 새 앱인지
  업데이트인지도 같은 규칙으로 가립니다
- 서버가 다시 확인합니다. 출시되지 않았거나, 이미 알렸거나, 가장 최근 출시본이 아니거나,
  스토어 앱이면 409 입니다. 팝업에서 "보내기" 를 눌러야 오는 `send=1` 이 없으면 보내지 않습니다
- 팝업에서 채널을 등록하러 가면 하던 버전의 ID 를 채널 칸에 싣습니다. 등록에 성공하면
  서버가 `?resume=<ID>` 로 돌려보내고, 화면이 그 버전의 팝업(출시 또는 보내기)을 다시
  띄웁니다. **자동으로 보내지는 않습니다.** 마지막 한 번은 사람이 누릅니다
- API 와 MCP 에는 열지 않습니다

## 대안과 기각 사유

### 출시된 버전이면 아무것이나 보낼 수 있게 한다

**규칙이 가장 단순합니다.** 단추를 어느 줄에 띄울지 따질 것이 없고, 버전 사이를 오가며
고친 앱도 원하는 버전을 알릴 수 있습니다.

기각한 이유는 사람들이 받는 버전과 글이 어긋나기 때문입니다. 1.1 이 나와 있는데 1.0 의
"출시되었습니다" 가 올라가면, 받은 사람은 글과 다른 버전을 봅니다. 업데이트 글이라면
더 헷갈립니다.

### 채널을 등록하면 그 자리에서 바로 보낸다

**사용자가 원한 "등록하자마자 전송" 에 가장 가깝습니다.** 단추를 한 번 덜 누릅니다.

기각한 이유는 채널 등록과 글 올리기가 다른 결정이라서입니다. 채널을 넣는 사람이 앱
관리자고, 출시는 올릴 권한만 있는 사람도 합니다. 채널 칸은 출시와 상관없이도 쓰이는데,
넣기만 하려던 사람의 채널에 글이 올라가면 되돌릴 수 없습니다. 팝업을 다시 띄우면 한 번
더 누르는 값으로 그 사고를 막습니다.

### API 와 MCP 에도 연다

**CI 나 에이전트로 출시하는 앱도 나중에 알릴 수 있습니다.** 웹과 API 가 갈라지지 않습니다.

기각한 이유는 되돌릴 수 없는 글을 사람 손을 거치지 않는 길에 하나 더 여는 것이라서입니다.
MCP 는 되돌릴 수 없는 일을 열지 않는다는 원칙이 있고 (ADR-0060, ADR-0077), 출시할 때
알리는 길(`announce`)은 이미 있습니다. 필요해지면 그때 엽니다.

### 철회했다 다시 출시하라고 안내한다

**새로 만들 것이 없습니다.** 지금도 되는 길이고, 알린 적 없는 버전이면 다시 출시할 때
알립니다.

기각한 이유는 철회하는 동안 그 앱이 스토어에서 사라지기 때문입니다. 받는 중이던 사람의
설치가 끊기고, 소식 하나 때문에 출시 상태를 흔드는 것은 앞뒤가 바뀌었습니다.

## 결과

**좋은 점**

- 채널을 늦게 등록한 앱도 첫 출시 소식을 보낼 수 있습니다
- 팝업에서 채널을 등록하러 갔다가 하던 일로 바로 돌아옵니다
- 보내는 규칙이 출시할 때와 같은 코드를 지나므로 두 번 올라가지 않습니다

**나쁜 점**

- 출시하고 한참 뒤에 소식이 올라갈 수 있습니다. 글에 출시 날짜가 없어 "방금 나왔다" 로
  읽힙니다
- CI 로 출시하는 앱은 나중에 알리려면 웹 콘솔로 와야 합니다
- 단추는 가장 최근 출시본에만 있어서, 더 높은 빌드를 알리지 않고 출시하면 앞 버전의 소식은
  영영 보낼 수 없습니다. 의도한 것이지만 처음 보는 사람은 단추가 사라진 이유를 모릅니다
- `?resume=<ID>` 가 붙은 주소를 누가 건네면 받은 사람의 화면에도 팝업이 뜹니다. 확인 단추를
  눌러야 하고 권한도 서버가 다시 보므로 해는 없지만, 뜻밖의 팝업일 수 있습니다
- "가장 최근 출시본인가" 는 보내기 전에 한 번만 봅니다. 그 사이 더 높은 빌드를 출시하고
  알리면 두 버전의 글이 함께 올라갈 수 있습니다. 드물고 글 하나가 더 붙는 정도라 막지 않았습니다
- 채널을 등록하러 간 뒤 그대로 다른 일을 하면 `resume` 이 채널 칸에 남습니다. 나중에 같은
  화면에서 채널을 넣으면 그때 팝업이 뜹니다
