# ADR-0080: 스토어 앱이 꺼져 있을 때의 업데이트 확인은 번들 안 LaunchAgent 가 같은 실행 파일로 한다

- 상태: 수락됨
- 날짜: 2026-10-26

## 맥락

스토어 앱은 떠 있는 동안 30분마다 목록을 읽고 앱을 자동으로 업데이트합니다 (ADR-0073).
그런데 스토어 앱을 자주 열지 않는 사람은 새 버전이 나와도 모른 채 옛 버전을 씁니다
(이슈 #74). 앱이 꺼져 있어도 무언가가 돌아야 합니다.

제약이 셋 있습니다.

- **번들은 서버가 조직마다 다시 쌉니다** (ADR-0046). 번들 ID 와 실행 파일 이름이 조직마다
  다르고, 서버는 맥이 아니라서 파일을 새로 쓸 수는 있어도 컴파일은 못 합니다
- 세션 토큰은 로그인 키체인에 있습니다. 같은 서명을 가진 실행 파일이면 묻지 않고 읽습니다
- 알림은 그것을 띄운 번들의 이름과 아이콘으로 나가야 사람이 무엇인지 압니다

## 결정

**번들 안 `Contents/Library/LaunchAgents/update-check.plist` 를 스토어 앱이
`SMAppService.agent(plistName:)` 로 등록하고, launchd 가 4시간마다 스토어 앱의 실행 파일을
`--check-updates` 로 띄웁니다.**

- 그 실행은 SwiftUI 앱을 띄우지 않고(`main.swift` 가 인자를 보고 가른다) 목록을 읽어 알림만
  띄우고 끝납니다. **받지 않습니다.** 창 없는 프로세스가 앱을 바꾸면 사람이 모르는 사이에
  일어납니다. 알림을 누르면 스토어 앱이 열리고, 열 때 하던 확인과 자동 업데이트가 그대로
  돕니다
- 스토어 앱이 떠 있으면 건너뜁니다. 그쪽이 이미 확인하고 화면에 보여줍니다
- 토큰이 없거나 401 이면 조용히 끝냅니다. 지우지도 갱신하지도 않습니다. 로그아웃과 갱신은
  스토어 앱이 열렸을 때 하던 대로 합니다 (ADR-0069)
- 업데이트는 한 통으로 묶고 같은 식별자로 보내 앞의 알림을 갈아끼웁니다. 알린 버전을
  기억해 두고(`notifiedBackgroundUpdates`), 새 버전이 하나라도 생길 때만 다시 알립니다.
  스토어 앱 자신은 넣지 않습니다. 열면 스스로 갈아끼웁니다
- 등록과 알림 권한 요청은 로그인한 뒤 앱 목록이 뜰 때 합니다. 계정 메뉴의
  "업데이트 알림" 을 끄면 등록을 내립니다. 기본은 켜짐입니다
- plist 는 `scripts/build-store-app.sh` 가 베이스 번들에, `StoreAppBundleRewriter` 가 조직
  번들에 씁니다. 서버 쪽은 원본을 버리고 새 번들 ID(라벨)와 실행 파일 이름으로 다시 씁니다.
  두 벌이 같은 값을 내는지는 시험이 봅니다

## 대안과 기각 사유

**로그인 항목으로 늘 떠 있는 헬퍼 앱(`SMAppService.loginItem`)** - 타이머를 마음대로 쓰고
알림을 누른 응답도 직접 받습니다. 그러나 `Contents/Library/LoginItems/` 에 번들이 하나 더
들어가고, 서버가 조직마다 그 번들의 ID 와 `Info.plist` 까지 다시 써야 하며, 서명할 것도
둘이 됩니다. 4시간에 한 번 몇 초 돌 일에 늘 떠 있는 프로세스를 둘 이유가 없습니다.

**스토어 앱이 창을 닫아도 메뉴 막대에 남아 계속 돈다** - 지금 확인 코드를 그대로 쓰고 받기까지
할 수 있습니다. 그러나 사람이 앱을 종료(⌘Q)하면 그만이라 "꺼져 있어도" 를 지키지 못하고,
늘 떠 있는 메뉴 막대 아이콘은 이 앱의 쓰임에 비해 무겁습니다.

**`~/Library/LaunchAgents` 에 plist 를 직접 써서 `launchctl` 로 올린다** - 번들 안 plist 를
서버가 다시 쓸 필요가 없습니다. 그러나 시스템 설정의 로그인 항목에 앱 이름이 아니라 정체를
알 수 없는 항목으로 보이고, 앱을 지워도 plist 가 남아 없는 파일을 계속 띄웁니다. 번들 안
plist 는 앱을 지우면 함께 사라집니다.

**서버 푸시(APNs)** - 주기가 아니라 출시 즉시 알립니다. 그러나 Developer ID 앱의 푸시는
조직마다 푸시 인증서와 서버 설정이 더 필요하고, 서버가 맥마다 기기 토큰을 관리해야 합니다.

**백그라운드에서 받기까지 한다** - 사람이 아무것도 안 해도 최신이 됩니다. 그러나 실행 중인
앱을 어떻게 할지(ADR-0074 는 앞에 나온 창에서 묻는다) 창 없이 정할 수 없고, 설치 실패를 알릴
자리도 없습니다.

## 결과

**좋은 점**
- 스토어 앱을 열지 않는 사람도 하루 몇 번 업데이트 소식을 받습니다
- 등록한 항목이 시스템 설정의 로그인 항목에 스토어 앱 이름으로 보이고, 거기서도 끌 수 있습니다
- 새로 들인 실행 파일도 권한도 없습니다. 토큰은 같은 실행 파일이 읽습니다

**나쁜 점**
- 처음 등록할 때 macOS 가 "백그라운드 활동" 알림을 한 번 띄웁니다. 막을 수 없습니다
- 알림 권한을 거절하면 확인은 돌지만 아무것도 보이지 않습니다. 앱은 그 상태를 따로 알리지 않습니다
- 이미 깔린 스토어 앱은 이 버전으로 업데이트되고 한 번 로그인한 화면이 떠야 등록됩니다
- 토큰을 갱신하지 않으므로 스토어 앱을 90일 넘게 열지 않으면 알림도 멈춥니다
- 같은 실행 파일이 두 모드로 돌아서, 앱 시작 코드에 인자를 보는 갈래가 하나 생겼습니다
- plist 를 두 곳(셸, 서버)에서 쓰므로 키를 더할 때 둘을 함께 고쳐야 합니다

**후속**
- 알림을 눌렀을 때 업데이트 목록만 보여주는 화면이 필요해지면 그때 만든다
