# ADR-0071: 앱 스크린샷은 로그인한 사람에게만 내준다

- 상태: 수락됨
- 날짜: 2026-10-01

## 맥락

앱 이름과 설명만으로는 무엇을 하는 앱인지 감이 오지 않을 때가 있어, 앱 상세에
스크린샷을 둡니다 (이슈 #40). 앱마다 5장까지, 한 장에 5MB 까지, PNG 나 JPEG 입니다.
버전이 아니라 앱에 묶고, 콘솔 앱 상세에서 올리고 지웁니다. 스토어 앱의 앱 상세에만
보입니다.

앱 아이콘은 같은 저장소(ADR-0045)에 두고 **로그인 없이** 내줍니다
(`/apps/:id/icon.png`). 스토어 앱이 목록의 줄마다 부르는 주소라 토큰을 붙이기
번거롭고, 그림의 내용이 감출 것이 아니기 때문입니다.

스크린샷은 사정이 다릅니다. 사내 앱 화면에는 고객 이름, 매출, 내부 시스템 주소 같은
사내 데이터가 찍힐 수 있습니다. 올리는 사람이 매번 가려서 올린다고 기대할 수 없습니다.

## 결정

**스크린샷은 `/api/v1/apps/:id/screenshots/:sid` 에서 로그인한 요청에만 내줍니다.**

- 스토어 앱은 `AsyncImage` 대신 세션 토큰을 붙여 직접 받습니다. 서버 주소와 다른
  호스트로는 토큰을 보내지 않습니다
- 콘솔은 같은 출처라 쿠키로 받습니다
- 응답은 `Cache-Control: private` 입니다. 공유 캐시에 남지 않게 합니다
- 서버의 이미지 메모리 캐시(`StoredImageCache`)에 넣지 않습니다. 한 장이 수 MB 라
  몇 장만 들어가도 아이콘과 브랜딩 이미지가 밀려납니다. 앱 상세를 열 때만 부르는
  주소라 매번 스토리지를 다녀와도 됩니다
- 앱을 지우면 스크린샷 오브젝트도 함께 지웁니다

## 대안과 기각 사유

**아이콘처럼 로그인 없이 내준다** - 스토어 앱이 `AsyncImage` 를 그대로 쓸 수 있고, 주소에
UUID 가 들어 있어 추측해서 받기는 어렵습니다. 그러나 주소가 한 번 새면(채팅에 붙여넣기,
브라우저 기록) 조직 밖에서도 열립니다. 사내 데이터가 찍힌 그림에 그 위험을 지울 이유가
없습니다.

**presigned URL 을 `AppDTO` 에 담아 내려준다** - 스토리지가 직접 내주므로 서버를 거치지
않습니다. 피드백 스크린샷이 이 방식입니다. 그러나 앱 목록을 내려줄 때마다 앱 수 × 5개의
서명을 만들어야 하고, URL 이 만료되면(기본 1시간) 목록을 다시 받기 전까지 그림이
깨집니다. 스토어 앱은 30분마다 목록을 다시 받지만, 노트북을 덮었다 열면 그 사이가
길어집니다.

## 결과

**좋은 점**
- 스크린샷 주소가 새어도 조직 밖에서는 열리지 않습니다
- 스토어 앱의 목록 응답이 커지지 않습니다. 주소만 담습니다

**나쁜 점**
- 스크린샷을 볼 때마다 서버가 스토리지에서 받아 그대로 넘깁니다. 큰 그림이 많으면
  서버 대역폭을 씁니다
- 스토어 앱이 그림 받기를 직접 해야 합니다. 받아둔 그림은 앱 메모리에만 두고, 로그아웃하면
  비웁니다
- 서버의 공개 주소(`PUBLIC_BASE_URL`)와 스토어 앱에 박힌 주소가 다르면 토큰을 보내지
  않아 그림이 안 보입니다
- 순서를 바꾸는 기능이 없습니다. 올린 순서대로 보이고, 바꾸려면 지우고 다시 올립니다

**후속**
- 순서 바꾸기는 요청이 오면 넣습니다
