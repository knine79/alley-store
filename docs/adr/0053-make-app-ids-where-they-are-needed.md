# ADR-0053: 포털 App ID 는 그것이 필요해진 자리에서 만든다

- 상태: 수락됨
- 날짜: 2026-09-17

## 맥락

[ADR-0005](0005-bundle-id-and-app-id-policy.md) 가 정한 3단 정책은 그대로입니다.
대부분의 앱은 포털에 등록하지 않고, 프로필이 필요하면 와일드카드 하나로 묶고, 특수
capability 를 쓰는 앱만 explicit App ID 를 만듭니다.

문제는 **어디서 만드느냐**였습니다. 앱 서명 화면에 식별자와 이름을 적는 폼이 하나
있었고, 둘 다 손으로 쳐야 했습니다.

그 값은 이미 스토어에 있습니다. 번들 ID 와 이름은 앱을 등록할 때 받았고, 와일드카드의
접두사는 `BUNDLE_ID_PREFIX` 에 있습니다. 같은 값을 다시 치게 하면 오타가 나고, **오타의
대가가 우리 쪽에 남지 않습니다.** App ID 는 Apple 개발자 계정에 만들어지고, 거기서
지우는 것은 Account Holder 나 Admin 역할만 할 수 있습니다. 프로비저닝 프로필이 물려
있으면 그것부터 지워야 합니다.

## 결정

**값을 묻지 않습니다. 만들 자리를 옮깁니다.**

| 무엇 | 어디서 | 값은 어디서 오나 |
| --- | --- | --- |
| 와일드카드 `<prefix>.*` | 앱 서명 화면 | 식별자는 `BUNDLE_ID_PREFIX`, 이름은 스토어 이름 |
| explicit App ID | 그 앱의 상세 화면 | 번들 ID 와 이름은 그 앱에 등록된 값 |

와일드카드는 특정 앱이 아니라 계정 단위 항목이라 앱 서명 화면에 남깁니다. 다만 이미
있으면 만드는 자리를 그리지 않고, 접두사가 비어 있으면 스토어 설정을 먼저 채우라고
합니다.

explicit App ID 는 **그 앱이 프로필이 필요한 권한을 쓰는 것이 보인 뒤에만** 자리가
납니다. 판단 기준은 워커가 서명을 멈출 때 쓰는 것과 같습니다 -
`com.apple.developer.` 로 시작하는 권한이 entitlements 에 있는가
(`EntitlementsPlist.requiresProvisioningProfile`). 기준을 한 곳에 두어서, 서명은
막혔는데 화면은 아무 말도 하지 않는 자리가 생기지 않게 합니다.

양쪽 모두 누르기 전에 **Apple 개발자 계정에 실제로 만들어진다는 것**과 **지우려면
어떤 역할이 필요한지**를 적습니다.

## 대안과 기각 사유

**앱을 등록할 때 자동으로 만든다** — 타이핑이 아예 사라집니다. 사람이 판단할 것도
없습니다.

기각한 이유는 셋입니다. **그 시점에 무엇이 필요한지 모릅니다.** entitlements 는 버전을
올릴 때 들어오고([ADR-0020](0020-uploader-provides-entitlements.md)), 앱을 만드는
화면에는 아직 바이너리가 없습니다. **대부분의 앱에는 필요가 없습니다.** 다 만들면
ADR-0005 가 피하려던 난립을 우리 손으로 만드는 셈입니다. 그리고 **되돌리기
어렵습니다.** 쓸모없는 엔트리가 계정에 쌓이는데 지우는 것은 우리가 못 합니다.

**지금처럼 손으로 적는 폼을 둔다** — 무엇이든 만들 수 있어 제일 자유롭습니다. 앱과
상관없는 App ID 가 필요해져도 이 화면에서 끝납니다.

기각한 이유는 **자유의 값이 오타이기 때문입니다.** 이미 시스템이 아는 값을 다시
치는 자리였고, 틀리면 Apple 계정에 남습니다. 앱과 상관없는 App ID 가 정말 필요하면
Apple 화면에서 만드는 편이 낫습니다. 그쪽은 지우는 것도 같은 자리에서 됩니다.

**와일드카드도 없앤다** — 그러면 이 화면은 순수하게 보는 곳이 되고, 첫 문장("여기서
보기만 합니다")과도 맞습니다.

기각한 이유는 **와일드카드가 앱 등록 규칙과 한 짝이기 때문입니다.** 식별자가
`BUNDLE_ID_PREFIX` 에서 나오므로, 사람이 Apple 화면에서 만들면 접두사와 어긋난 것을
만들 수 있습니다. 스토어가 자기 규칙으로 만들어주는 편이 어긋날 자리를 없앱니다.

## 결과

**좋은 점**

- 번들 ID 를 다시 치는 자리가 없어집니다. 만들어지는 값은 스토어가 아는 값과 같습니다
- 와일드카드가 앱 등록 규칙과 어긋날 수 없습니다
- 필요 없는 앱에는 자리가 나오지 않습니다. 대부분의 앱이 그렇습니다
- 누르기 전에 무엇이 어디에 만들어지는지, 지우려면 누가 필요한지 읽게 됩니다

**나쁜 점**

- **판단은 여전히 사람 몫입니다.** 프로필이 필요한 권한을 쓴다고 App ID 가 반드시
  없는 것은 아닙니다. Xcode 로 이미 만들어뒀을 수 있고, 그때는 눌러도 Apple 이
  거절합니다. 화면은 그 말을 옮길 뿐입니다
- **만들어지는지는 API 키 권한에 달렸습니다.** 조회만 되는 키면 누를 때 거절당합니다.
  그것은 눌러봐야 압니다
- 앱 상세에 관리자만 보는 구역이 하나 늘었습니다. 그 화면은 이미 깁니다
- 접두사를 바꾸면 옛 와일드카드는 계정에 남습니다. 지우는 것은 사람이 Apple 화면에서
  해야 합니다
- 앱과 상관없는 App ID 를 콘솔에서 만들 길이 없어졌습니다. 그런 일이 잦아지면 이
  결정을 다시 봐야 합니다
