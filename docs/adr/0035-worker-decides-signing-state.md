# ADR-0035: 서명 여부는 사람에게 묻지 않고 워커가 판정한다

- 상태: 수락됨
- 날짜: 2026-09-10

## 맥락

업로드 화면에 라디오가 하나 있었습니다.

> ( ) 서명 전입니다. 서명·공증해 주세요
> ( ) 이미 서명·공증을 마쳤습니다

두 번째를 고르면 서버가 이렇게 했습니다.

```swift
if version.uploadKind == .signed {
    try version.transition(to: .ready)   // 아무도 확인하지 않는다
}
```

**그 말을 검사하는 자리가 없었습니다.** 서명 안 된 앱을 올리면서 "마쳤습니다" 를
고르면 워커를 건너뛰고 곧장 배포 준비됨이 됩니다. 그대로 출시하면 받는 사람의 맥이
Gatekeeper 에서 막습니다. 거짓말이 필요한 것도 아닙니다. **모르고 잘못 고르면
똑같이 됩니다.** CI 가 만든 산출물을 올리는 사람이 그 파이프라인이 공증까지
했는지 아닌지를 늘 아는 것은 아닙니다.

같은 화면에서 번들 ID 를 묻는 칸은 이미 없앴습니다([ADR-0034](0034-worker-decides-bundle-id-for-disk-images.md)).
**번들 안에 답이 적혀 있는데 사람에게 옮겨 적으라고 하지 않는다** 는 것이 그때의
이유였고, 서명 여부는 정확히 같은 종류의 값입니다.

## 결정

**라디오를 없앱니다.** 모든 업로드가 워커를 거치고, 워커가 번들을 열어 판정합니다.

```
업로드 → 워커가 codesign·stapler 로 확인
        ├ 이미 됨 → 서명·공증 건너뜀 → 배포 준비됨
        └ 아님   → 서명·공증 → 배포 준비됨
```

판정은 `SignatureInspection` 이 합니다. 셋을 **모두** 만족해야 "다 됐다" 입니다.

| 무엇 | 어떻게 | 아니면 |
| --- | --- | --- |
| Developer ID 서명 | `codesign -dv` 의 `Authority=` | 서명한다 |
| **우리 팀** | `TeamIdentifier=` 가 워커의 identity 와 같은가 | 우리 이름으로 다시 서명한다 |
| 공증 티켓 | `xcrun stapler validate` | 공증받아 붙인다 |

셋을 따로 보는 이유가 각각 있습니다. ad-hoc 서명은 그 맥에서만 열립니다. 남의 팀
서명을 그대로 내보내면 **이 스토어가 남의 서명을 중계하는 셈** 이 됩니다. 티켓이
없으면 받은 사람의 맥이 Apple 에 물어봐야 하고, 사내망처럼 막힌 곳에서는 그 조회가
실패해 앱이 안 열립니다.

**애매하면 서명하는 쪽으로 기웁니다.** 이미 된 것을 다시 하면 몇 분을 더 쓰지만,
안 된 것을 됐다고 넘기면 사용자 맥에서 안 열립니다. 두 실패의 무게가 다릅니다.

### `uploadKind` 를 지우지는 않았습니다

요청 본문의 필드와 CLI 의 `--signed` 플래그는 옵셔널로 남겨두고 **서버가 무시합니다.**
지우면 그 값을 보내던 스크립트가 400 으로 죽습니다. 받아만 두고 안 쓰는 편이
낫습니다. 저장하는 자리는 늘 미서명 슬롯입니다.

## 대안과 기각 사유

**라디오는 두고 워커가 검증만 한다** — 사람이 고른 값이 틀리면 알려줄 수 있고,
"서명했다고 하셨는데 아니네요" 라는 메시지가 친절합니다. 그러나 **묻는 값이 하는
일이 없어집니다.** 결과는 어차피 워커의 판정으로 정해지는데 화면에는 고르라고
나옵니다. 답이 결정에 아무 영향을 주지 않는 질문은 사람을 헷갈리게만 합니다.

**서버가 판정한다** — 워커에 안 보내니 왕복이 없습니다. 그러나 서버는 리눅스
컨테이너이고 `codesign` 도 `stapler` 도 없습니다. 서명 구조를 직접 파싱하는 코드를
쓰는 것은 Apple 도구가 하는 일을 다시 만드는 것이고, 그 코드가 틀리면 틀린 줄
모릅니다.

**늘 다시 서명한다 (판정을 아예 안 한다)** — 가장 단순하고 가장 안전합니다. 코드가
줄어듭니다. 그러나 이미 공증까지 마친 산출물에 매번 몇 분을 더 씁니다. 공증은
Apple 서버를 왕복하는 일이라 우리가 줄일 수 없는 시간입니다. 더 나쁜 것은 **이미
서명된 번들을 다시 서명하면 기존 티켓이 무효가 되어** 공증을 반드시 다시 받아야
한다는 점입니다. 건너뛸 수 있는데 굳이 그러지 않을 이유가 없습니다.

## 결과

**좋은 점**

- **검사 없이 배포 준비됨으로 가는 길이 없어졌습니다.** 모든 산출물이 워커를 지납니다
- 화면에서 고를 것이 하나 줄었습니다. 틀리게 고를 방법도 함께 사라졌습니다
- 남의 팀 서명과 ad-hoc 서명을 이제 잡아냅니다. 예전에는 "마쳤습니다" 한 마디로
  통과했습니다
- 이미 된 것은 여전히 건너뜁니다. 느려지지 않았습니다

**나쁜 점**

- **이미 완성된 번들도 워커를 기다립니다.** 예전에는 업로드가 끝나면 곧장 배포
  준비됨이었는데, 이제 잡이 잡히고 다운로드·검사까지 갑니다. 워커가 바쁘면 그만큼
  기다립니다. 검사 자체는 몇 초지만 큐에 서는 시간은 다릅니다
- **워커가 없으면 아무것도 준비되지 않습니다.** 예전에는 완성본 경로만은 워커 없이
  돌았습니다. 그 우회로가 사라져서 워커가 단일 장애점에 더 가까워졌습니다
- **판정이 보수적이라 헛수고가 생깁니다.** `codesign` 출력을 문자열로 읽는데, 형식이
  바뀌거나 예상 밖의 서명이면 "안 됐다" 로 떨어져 다시 서명합니다. 결과는 맞지만
  시간을 씁니다
- `uploadKind` 가 API 에 남아 있는데 아무 일도 하지 않습니다. **문서를 읽지 않고
  필드만 보는 사람은 이게 뭔가 한다고 생각합니다.** 지우는 것은 옛 클라이언트가
  다 사라진 뒤로 미룹니다
