# ADR-0067: 앱 아이콘은 워커가 번들에서 뽑는다

- 상태: 수락됨
- 날짜: 2026-10-01

## 맥락

앱 아이콘은 한 경로로만 들어왔습니다. 웹 콘솔의 새 앱 등록 화면에서 브라우저가 zip 을
열어 `Contents/Resources/*.icns` 에서 PNG 를 꺼내 올렸습니다 (ADR-0030).

운영에서 처음 dmg 로 등록한 앱이 아이콘 없이 출시됐습니다. 설치한 앱은 Dock 에 아이콘이
잘 보였습니다. 번들에는 아이콘이 있는데 스토어만 몰랐습니다. 같은 구멍이 셋 있었습니다.

- **dmg.** 브라우저가 열 수 없습니다 (ADR-0032). 워커는 dmg 를 풀지만 버전과 번들 ID
  만 보고했습니다
- **CLI 와 버전 화면.** 추출이 새 앱 등록 화면에만 있어서, 앱의 아이콘이 바뀌어도
  스토어는 처음 것을 계속 보였습니다
- **`Assets.car` 에만 아이콘이 든 번들.** `CFBundleIconName` 만 쓰는 앱, Icon
  Composer 로 만든 앱이 그렇습니다. `Assets.car` 는 브라우저가 풀 수 있는 형식이 아닙니다

모든 업로드가 지나가는 곳은 서명 워커뿐이고, 워커는 macOS 입니다.

## 결정

**서명이 끝난 번들에서 워커가 아이콘을 PNG 로 뽑아 올리고, 서버가 검사해 앱 아이콘으로
붙입니다.**

- 서버는 모든 잡의 지시서에 아이콘 업로드 주소(`iconUploadURL`)를 넣습니다. 키는
  `apps/<앱>/versions/<버전>/icon.png` 입니다
- 워커는 `Info.plist` 의 `CFBundleIconName`, 없으면 `CFBundleIconFile` 이름으로
  `Bundle.image(forResource:)` 에서 아이콘을 찾아 512×512 PNG 로 그려 올리고, 크기를
  `iconSize` 로 보고합니다. 에셋 카탈로그와 `.icns` 를 함께 찾습니다
- 둘 다 없으면 뽑지 않습니다. 일반 앱 아이콘을 걸면 진짜처럼 보여서 없는 것보다 나쁩니다
- 서버는 스토리지에서 그림을 읽어 브라우저 업로드와 같은 규칙(정사각형, 32px 이상)으로
  보고, 맞으면 **이미 있는 아이콘도 갈아끼웁니다.** 실제로 나가는 번들이 진실입니다
- 다만 같은 앱에 빌드 번호가 더 큰 버전이 이미 서명돼 있으면(준비됨, 출시됨) 붙이지
  않습니다. 실패했던 옛 빌드를 다시 돌려 성공하면 아이콘이 옛것으로 되돌아가고, 그때
  지워지는 최신 아이콘은 되살릴 수 없습니다
- 어느 쪽에서 무엇이 잘못돼도 잡은 실패시키지 않습니다. 아이콘은 없어도 되는 값입니다
- 브라우저 추출은 그대로 둡니다. 등록 화면에서 미리 보여주는 데 쓰이고, 워커가 아이콘을
  모르는 예전 버전이어도 zip 등록은 지금처럼 아이콘을 얻습니다

두 필드 모두 옵셔널이라 예전 워커와 새 서버, 새 워커와 예전 서버가 섞여도 깨지지
않습니다. 예전 워커는 자리를 받고도 올리지 않을 뿐이고, 예전 서버는 자리를 주지 않으니
새 워커가 뽑지 않습니다.

## 대안과 기각 사유

### `NSWorkspace.icon(forFile:)` 로 받는다

Finder 와 Dock 이 그리는 것과 같은 길이라, 번들이 아이콘을 어떻게 담았든 macOS 가
알아서 찾아줍니다. 처음에는 이것으로 만들었습니다.

기각합니다. 이 맥에서 실행할 수 없는 앱이라고 보면 아이콘 위에 금지 표시를 덧씌웁니다.
시험 픽스처에서 실제로 그렇게 나왔습니다. 워커 맥의 macOS 가 앱의 최소 OS 보다 낮으면
운영에서도 그 그림이 스토어에 걸립니다. 아이콘을 밝히지 않은 번들에는 일반 앱 아이콘을
돌려주는데, 그것도 가려낼 방법이 없습니다.

### 브라우저가 `Assets.car` 까지 읽는다

서버와 워커를 건드리지 않고, 올리기 전에 아이콘을 보여줄 수 있습니다.

기각합니다. `Assets.car` 는 공개 문서가 없는 형식이고, 안에 든 아이콘이 PNG 가 아니라
압축된 비트맵이나 Icon Composer 의 레이어일 수 있습니다. 풀어낸다 해도 dmg 와 CLI
경로는 여전히 브라우저를 지나지 않습니다.

### 상태 보고 JSON 에 PNG 를 base64 로 싣는다

presigned 주소를 새로 만들 필요가 없고, 서버가 스토리지를 다시 읽지 않아도 됩니다.

기각합니다. 서버의 기본 본문 상한이 1MB 이고, 1024 아이콘은 base64 로 부풀리면 그것을
넘을 수 있습니다. 바이너리는 presigned 주소로 주고받는다는 원칙(ADR-0009)과 dmg 를
올리는 길(ADR-0050)을 그대로 따르는 편이 읽기 쉽습니다.

### 출시할 때 아이콘을 바꾼다

출시하지 않은 빌드가 목록의 아이콘을 바꾸지 않습니다. 아이콘을 바꾼 베타를 올려도
출시본의 아이콘이 그대로 남습니다.

지금은 기각합니다. 아이콘을 버전마다 보관하고 출시 경로(웹 콘솔, MCP, CLI 의
`--release`)마다 바꿔 끼우는 일을 더해야 합니다. 사내 앱에서 아이콘을 바꾼 빌드를
출시하지 않고 오래 두는 경우는 드뭅니다.

## 결과

### 좋은 점

- dmg, CLI, 버전 화면, `Assets.car` 어느 경로로 올려도 아이콘이 붙습니다
- 앱 아이콘이 바뀌면 다음 빌드에서 스토어도 따라갑니다
- 올리는 사람이 할 일이 없습니다

### 나쁜 점

- 서명을 마친 빌드가 출시 전에 목록 아이콘을 바꿉니다
- 이미 올라간 앱은 새 빌드를 올려야 아이콘이 생깁니다
- 아이콘을 그리는 일이 워커 맥의 macOS 에 달렸습니다. 워커가 앱보다 낮은 macOS 면
  Icon Composer 아이콘이 에셋 카탈로그의 대체 그림으로 그려질 수 있습니다
- `Info.plist` 가 가리키는 이름이 실제 리소스와 다르면 macOS 는 아이콘을 찾는데 스토어는
  못 찾을 수 있습니다. 그때는 아이콘 없이 나갑니다
- 브라우저 업로드와 워커 보고, 아이콘이 들어오는 길이 둘이 됐습니다. 둘 다
  `AppIconController.servedURL` 로 같은 주소를 적어서 화면은 구분하지 않습니다

### 후속 과제

- 출시본 기준으로 아이콘을 보여줘야 한다는 요구가 생기면 위의 세 번째 대안으로 옮깁니다
