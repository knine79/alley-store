# ADR-0070: 앱 분류는 코드에 정한 목록에서 고른다

- 상태: 수락됨
- 날짜: 2026-10-01

## 맥락

앱에는 `category` 칸이 있었습니다. 자유 텍스트였고, 새 앱 등록과 버전 확인 화면에서만
적을 수 있었고, 콘솔 앱 목록 카드에 작게 보이는 것이 전부였습니다. 스토어 앱은 받기만
하고 쓰지 않았습니다. 적을 이유가 없으니 아무도 적지 않았습니다.

스토어 앱에서 분류로 목록을 거르려면 값이 맞아야 합니다. 자유 텍스트로는 "개발 도구",
"개발도구", "Dev Tools" 가 서로 다른 분류가 됩니다.

## 결정

**분류는 코드에 정한 여덟 개(`AppCategory`) 중 하나를 고릅니다.** 개발 도구, 업무,
생산성, 커뮤니케이션, 디자인, 유틸리티, 데이터·분석, 기타입니다. 비워두면 미분류입니다.

- 저장과 API 에는 영문 값(`developer-tools`)이 오갑니다. 화면 이름은 바꿔도 되지만
  저장 값은 바꾸지 않습니다
- 서버는 목록에 없는 값을 거절합니다. 화면 이름("개발 도구")으로 보내면 저장 값으로
  바꿔 받습니다. 예전 클라이언트와 CLI 가 그렇게 보낼 수 있습니다
- 이미 저장된 값 중 화면 이름과 같은 것은 마이그레이션이 저장 값으로 옮깁니다.
  **목록에 없는 값은 지우지 않습니다.** 읽는 쪽이 미분류로 다루므로 남겨둬도 해가 없고,
  지우면 사람이 적은 것을 되살릴 수 없습니다. 앱 정보를 다시 저장하면 미분류가 됩니다
- 콘솔은 고르는 칸(`<select>`)을 보여주고, 스토어 앱은 목록과 상세에 분류를 보이고
  툴바에서 거릅니다. 거르기 칸에는 목록에 실제로 있는 분류만 냅니다

## 대안과 기각 사유

**관리자가 목록을 관리한다** - 조직마다 사정에 맞는 분류를 둘 수 있습니다. 사내 앱이
"인사", "재무" 처럼 부서로 갈리는 조직에는 이쪽이 맞습니다. 그러나 목록을 고치는 화면,
저장하는 표, 분류를 지웠을 때 그 분류를 쓰던 앱을 어떻게 할지까지 함께 와야 합니다.
사내 앱은 갈래가 많지 않아 고정 목록으로도 충분하다고 봤습니다.

**자유 텍스트를 그대로 두고 보여주기만 한다** - 고칠 것이 가장 적고 무엇이든 적을 수
있습니다. 그러나 거르기를 할 수 없습니다. 같은 분류를 다르게 적은 앱이 따로 놀아,
거르면 앱이 빠집니다.

**Mac App Store 분류를 그대로 쓴다** - 이미 정리된 목록이고 개발자에게 익숙합니다.
그러나 21개 중 게임, 의료, 날씨처럼 사내 스토어에 맞지 않는 것이 많고, 고르는 칸이
길어져 고르기 어려워집니다.

## 결과

**좋은 점**
- 스토어 앱에서 분류로 거를 수 있습니다
- 예전 값은 지워지지 않고, 예전 클라이언트가 화면 이름으로 보내도 받습니다

**나쁜 점**
- 조직이 분류를 바꾸려면 코드를 고쳐야 합니다
- 화면 이름이 한국어로 박혀 있습니다. 다른 언어를 쓰는 조직은 고쳐야 합니다
- 저장된 값이 목록에 없으면 콘솔에서 "미분류" 로 보이고, 그대로 저장하면 그 값이
  사라집니다. 무엇이 적혀 있었는지 화면에 보이지 않습니다

**후속**
- 조직마다 분류를 바꾸고 싶다는 요청이 오면 관리자 목록으로 옮기는 것을 다시 봅니다
