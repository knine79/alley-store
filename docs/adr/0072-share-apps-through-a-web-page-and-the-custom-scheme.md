# ADR-0072: 앱 공유 링크는 웹 페이지가 받고 커스텀 스킴으로 스토어 앱을 부른다

- 상태: 수락됨
- 날짜: 2026-10-02

## 맥락

개발자가 슬랙에서 자기 앱을 알리고 싶어도 붙일 주소가 없었습니다 (이슈 #55). 콘솔 앱
상세(`/apps/:id`)는 그 앱을 손댈 수 있는 사람만 들어가고(ADR-0051), 받는 사람에게
필요한 것은 눌러서 바로 받는 주소입니다.

받는 사람은 둘 중 하나입니다. 스토어 앱이 깔려 있으면 그 앱 상세가 열려야 하고, 없으면
스토어 앱 설치로 안내해야 합니다.

## 결정

**앱마다 공유 주소 `/a/<앱 ID>` 를 둡니다. 서버의 웹 페이지이고, 페이지가 스토어 앱의
커스텀 스킴(`<scheme>://apps/<앱 ID>`)을 부릅니다.**

- 페이지는 **로그인 없이** 열립니다. 출시된 앱의 이름, 한 줄 소개, 아이콘만 보입니다
- **출시 전 앱과 없는 앱은 같은 404 화면**입니다. 형식이 틀린 주소도 같습니다. 주소를
  지어서 출시 전 앱이 있는지 떠볼 수 없게 합니다
- 스토어 앱 자신의 공유 주소는 `/get` 으로 보냅니다. 스토어 앱 목록에는 자기가 없어서
  링크로 열 상세가 없습니다
- 페이지가 열리면 **버튼 없이 "여는 중입니다" 만 보이고** 스크립트가 바로 스킴을
  부릅니다. 브라우저는 앱이 깔려 있는지 알려주지 않아서 포커스로 짐작합니다. 2초 뒤에도
  페이지가 포커스를 쥐고 있거나, 다른 곳에 갔다가 포커스가 돌아오면 **"{스토어 앱
  이름}에서 보기" 와 "{스토어 앱 이름} 다운로드" 를 위아래로** 꺼냅니다. 보기가 위에 있고
  강조색입니다. 버튼은 나타나기만 하고 순서나 색이 바뀌지 않습니다. 스크립트가 없으면
  처음부터 보입니다
- 레이블의 이름은 관리자가 정한 스토어 앱 이름(`StoreAppSettings.appName`)입니다
- 스킴은 `StoreAppSettings.urlScheme` 입니다. 서버가 조립해 내보낸 스토어 앱
  번들(ADR-0046)이 등록한 값이 이것입니다
- Open Graph 태그를 붙입니다. 메신저 서버가 이 페이지를 읽을 수 있는 조직에서는 카드로
  펼쳐집니다
- `AppDTO.shareURL` 에 출시된 앱의 공유 주소를 서버가 절대 주소로 실어줍니다. 스토어
  앱의 툴바에 **공유** 아이콘이 생깁니다. 누르면 그 아이콘에 붙어 macOS 공유 창이 뜨고,
  맨 위에 "링크 복사" 를 더해 둡니다. 처음에는 앱 상세 머리에 설치 버튼과 나란히 뒀는데,
  한쪽에만 아이콘이 있어 어울리지 않아 툴바로 옮겼습니다. 그 자리에 있던 새로 고침은
  계정 메뉴의 "업데이트 확인" 과 ⌘R 로 옮겼습니다

### 스토어 앱은 링크를 로그인 뒤까지 들고 있습니다

스토어 앱을 처음 받은 사람은 설치하고, 페이지로 돌아와 "스토어 앱에서 열기" 를 다시
누릅니다. 그때 앱은 로그인 전입니다. 앱은 받은 링크를 버리지 않고(`AppLinkInbox`) 로그인을
마치고 목록을 다 읽은 뒤에 그 앱을 엽니다. 목록에 없으면 "찾을 수 없다" 고 알립니다.

설치 파일에 링크를 실어 첫 실행 때 바로 그 앱으로 가는 길은 없습니다. 브라우저가 받은
파일에 페이지의 정보를 붙일 방법이 없고, 서버가 사람마다 다른 dmg 를 만들 수도 없습니다.

### 링크 URL 은 로그인 콜백과 같은 Apple Event 처리기로 받습니다

ADR-0068 이 건 GetURL 처리기를 그대로 씁니다. 호스트로 가릅니다(`auth` 는 로그인,
`apps` 는 공유 링크). 공유 링크는 앱이 꺼져 있을 때 누르는 경우가 많아서 두 가지를
더했습니다.

- 처리기를 `applicationWillFinishLaunching` 에서도 겁니다. 앱을 띄운 URL 은 그 뒤에
  옵니다. 예전처럼 `applicationDidFinishLaunching` 에서만 걸면 그것을 놓칩니다
- 링크를 받고 1초 뒤에 보이는 창이 없으면 자기 번들을 `NSWorkspace` 로 한 번 더 엽니다.
  Dock 아이콘을 누른 것과 같은 재실행 이벤트가 와서 SwiftUI 가 창을 만듭니다. 창을 닫아둔
  채 링크를 누르면 링크는 받아도 창이 없었습니다. SwiftUI 창을 AppKit 에서 직접 여는
  공개된 길이 없고, `newWindowForTab:` 는 SwiftUI 창이 받지 않았습니다

## 대안과 기각 사유

### 유니버설 링크

**주소 하나로 앱이 있으면 앱이, 없으면 웹이 열립니다.** 브라우저의 "이 앱을
여시겠습니까" 도 없고 페이지가 짐작할 일도 없습니다. 이 기능에 가장 맞는 도구입니다.

기각한 이유는 Associated Domains entitlement 가 프로비저닝 프로필이 있어야 붙기
때문입니다. 스토어 앱은 Developer ID 로 서명하고 프로필 없이 나갑니다. 프로필을 붙이려면
조직마다 개발자 포털에서 App ID 와 프로필을 만들어야 하고, 서버가 조립하는 번들(ADR-0046)
에 그것까지 실어야 합니다. 설치가 무거워지는 값에 비해 얻는 것이 브라우저 확인 창
하나입니다.

### 페이지에 로그인을 건다

**앱 이름과 소개가 조직 밖으로 나갈 길이 없습니다.** 주소가 새어도 로그인하지 않은
사람은 아무것도 보지 못합니다.

기각한 이유는 웹으로 로그인하면 그 사람이 개발자가 되기 때문입니다 (ADR-0056). 앱을
받으러 온 사람을 거기로 보내면 안 됩니다. 페이지가 보여주는 것도 스토어 앱에 로그인한
사람이면 누구나 보는 목록의 한 줄이고, 아이콘은 이미 로그인 없이 나갑니다.

### 주소에 번들 ID 를 쓴다

**사람이 읽을 수 있고 손으로 적을 수도 있습니다.** 번들 ID 는 바뀌지 않습니다.

기각한 이유는 길고, 지어서 넣어볼 수 있기 때문입니다. 출시 전 앱의 정보는 어차피 보이지
않지만 앱 ID 를 쓰면 떠볼 거리 자체가 없습니다. 스토어 앱도 앱을 이미 ID 로 다룹니다.
메신저 카드가 펼쳐지면 주소는 가려지므로 읽기 어려운 것이 크게 문제 되지 않습니다.

### 반응이 없으면 버튼의 순서와 색을 바꾼다

**처음부터 두 버튼을 보여주고, 앱이 안 열린 것 같으면 받기 쪽을 앞세웁니다.** 버튼이
늘 보이므로 사람이 기다릴 일이 없고, 앱이 없는 사람은 받기가 눈에 먼저 들어옵니다.

처음에 이렇게 만들었다가 버렸습니다. 짐작이 틀리면 앱이 열렸는데도 눈앞의 "열기" 버튼이
"받기" 로 바뀌어 당황스러웠습니다. 틀릴 수 있는 정보로는 이미 보이는 것을 바꾸지 않고,
없던 것을 꺼내는 데만 씁니다.

### 스토어 앱 로그인 때 쿠키를 심어 앱이 있는지 판단한다

**스토어 앱은 기본 브라우저로 로그인하므로(ADR-0068), 그 응답에서 쿠키를 심으면 이
브라우저 주인에게 앱이 있다는 꽤 믿을 만한 단서가 됩니다.** 단서가 있으면 보기 버튼만
보여줄 수 있습니다.

기각한 이유는 틀릴 수 있기 때문입니다. 앱을 지워도 쿠키는 남고, 다른 브라우저나 시크릿
창에서는 단서가 없습니다. 틀렸을 때 다운로드 길이 숨으면 앱이 없는 사람이 막힙니다.

### 링크를 SwiftUI `onOpenURL` 로 받는다

**처리기를 직접 걸 필요가 없고, 앱을 띄운 URL 도 SwiftUI 가 알아서 넘겨줍니다.**

기각한 이유는 ADR-0068 과 같습니다. `WindowGroup` 이 URL 을 받을 창을 고르지 못하면 새
창을 띄웁니다. 이 앱은 창이 하나여야 합니다.

## 결과

**좋은 점**

- 슬랙에 붙일 주소가 생겼습니다. 스토어 앱 툴바의 공유에서 바로 복사합니다
- 스토어 앱이 없는 사람도 같은 주소에서 설치로 이어지고, 설치 뒤 로그인하면 그 앱으로
  갑니다
- 출시 전 앱은 주소로 드러나지 않습니다

**나쁜 점**

- **사내망에만 열린 스토어에서는 메신저 미리보기가 펼쳐지지 않습니다.** 슬랙 서버가
  페이지를 읽지 못합니다. 이슈가 바란 카드는 스토어를 바깥에 연 조직에서만 보입니다
- **출시된 앱의 이름·소개·아이콘은 주소를 아는 누구에게나 보입니다.** 스토어를 바깥에
  연 조직이면 조직 밖에도 보입니다. 검색 엔진에는 `noindex` 로 막아 둡니다
- **스토어 앱이 있는지는 짐작입니다.** 앱이 열린 뒤 사람이 이 탭으로 돌아오면 필요
  없는 버튼이 나타납니다. Safari 는 등록되지 않은 스킴에 "주소가 올바르지 않다" 는 경고를
  띄웁니다
- **처음 설치한 사람은 링크를 한 번 더 눌러야 합니다.** 페이지가 그렇게 안내합니다
- 창이 없을 때 자기 번들을 다시 여는 방법은 SwiftUI 의 재실행 동작에 기댑니다. 문서에
  약속된 동작이 아니라 확인한 동작입니다
- 같은 스킴을 등록한 다른 앱이 있으면 그 앱이 링크를 받습니다. ADR-0068 의 로그인
  콜백과 같은 문제이고, 스킴을 겹치지 않게 짓는 것이 운영자 몫으로 남습니다

**후속**

- 사내망 스토어에서도 카드를 펼치려면 Slack 앱을 Socket Mode 로 붙여(서버가 바깥으로
  접속) `link_shared` 이벤트에 `chat.unfurl` 로 답할 수 있습니다. 요청이 오면 검토합니다
