# ADR-0039: 확정 전 등록만 지울 수 있다

- 상태: 수락됨
- 날짜: 2026-09-11

## 맥락

[ADR-0034](0034-worker-decides-bundle-id-for-disk-images.md) 에 이렇게 적어뒀습니다.

> **확정에 실패하면 어중간한 앱이 남습니다.** (…) 치우는 것은 사람 몫입니다.

**치울 수단을 만들지 않았습니다.** dmg 를 올리면 임시 번들 ID 로 앱이 만들어지고,
업로드나 서명이 실패하면 그대로 남습니다. 목록에서는 빠지고 안내줄 링크로만 닿는데,
거기 가도 할 수 있는 일이 없습니다. 실제로 실패가 몇 번 나자 지울 수 없는 등록이
쌓였습니다.

겹침도 여기서 나옵니다. 같은 앱을 다시 올리려고 새로 등록하면, 나중에 워커가 번들
ID 를 확정할 때 **먼저 만든 쪽과 부딪혀** 실패합니다. 등록 시점에는 임시값이라 겹치는지
알 수 없습니다.

## 결정

**번들 ID 가 확정되지 않은 앱만 지울 수 있습니다.** 오너와 관리자만, 앱 상세 화면에서.

지우면 올린 파일(스토리지 오브젝트)과 버전·서명 잡까지 함께 사라집니다. 스토리지를
먼저 치웁니다. 행을 먼저 지우면 **어떤 오브젝트가 남았는지 알아낼 방법이 없어집니다.**
반대 순서로 실패하면 행이 남아 다시 시도할 수 있습니다.

### 확정된 앱은 지우지 않습니다

**번들 ID 가 정해졌다는 것은 누군가 설치했을 수 있다는 뜻입니다.** 다운로드 이력,
피드백, 배포 토큰이 매달려 있고, 받아간 맥에서는 이미 그 앱이 그 ID 로 자리를
잡았습니다. 지우는 것과 되돌리는 것이 같지 않습니다.

확정 전 앱에는 그런 것이 하나도 없습니다. 출시된 적이 없고([ADR-0034]
(0034-worker-decides-bundle-id-for-disk-images.md) 가 막습니다), 목록에 나온 적도
없고, 이름조차 파일 이름에서 짐작한 값입니다. **한 번도 무엇인지 정해진 적 없는 행**
만 지웁니다.

### 겹친다는 사실은 확정할 때 처음 드러납니다

그래서 두 자리에 말을 넣습니다.

| 언제 | 무엇을 말하나 |
| --- | --- |
| 등록 화면을 열 때 | 확인 중인 등록이 N개 있다. 같은 앱이면 새로 만들지 말고 거기에 올리거나 지워라 |
| 워커가 확정하다 부딪힐 때 | 어느 앱이 그 ID 를 쓰는지, 같은 앱이면 새 버전으로 올리고 이 등록은 지워라 |

앞의 것은 **막지 않습니다.** 등록 시점에는 번들 ID 를 모르므로 겹칠지 아닐지 알 수
없고, 모르면서 막으면 멀쩡한 등록까지 막습니다.

### 팝업으로 한 번 받습니다

되돌릴 수 없고 파일까지 지웁니다. [ADR-0037](0037-confirm-disk-image-upload-in-a-dialog.md)
에서 만든 `<dialog>` 방식을 그대로 씁니다. `data-confirm` 이 붙은 폼이면 어느 것이든
쓸 수 있게 해뒀습니다.

## 대안과 기각 사유

**어떤 앱이든 지울 수 있게 한다** — 오타로 만든 앱도 치울 수 있어 더 편합니다.
그러나 출시된 앱을 지우면 받아간 사람들의 업데이트 경로가 끊기고, 다운로드 이력과
피드백이 함께 사라집니다. 그건 "지우기" 가 아니라 "내리기(archive)" 로 다뤄야 하는
다른 결정입니다.

**방치된 확정 전 앱을 서버가 자동으로 치운다** — 사람 손이 아예 안 갑니다.
[ADR-0019](0019-abandoned-draft-cleanup.md) 의 `draft` 청소와 같은 모양입니다.
그러나 **올린 사람이 고치는 중일 수도 있습니다.** 며칠 뒤에 사라지는 것과 지금
지우는 것은 다른 문제고, 자동 청소를 넣더라도 손으로 지우는 길은 여전히 필요합니다.
자동 청소는 나중에 붙일 수 있습니다.

**등록할 때 겹침을 막는다** — 가장 이르게 잡습니다. 그러나 확정 전에는 번들 ID 가
임시값이라 무엇과 겹칠지 알 방법이 없습니다. 알 수 없는 것을 막으면 멀쩡한 등록이
막힙니다.

## 결과

**좋은 점**

- **막다른 골목이 없어졌습니다.** 실패한 등록을 올린 사람이 직접 치웁니다
- 스토리지 오브젝트가 함께 사라집니다. 행만 지우면 아무도 못 찾는 파일이 남습니다
- 확정된 앱은 실수로도 지울 수 없습니다. 문턱이 상태에 박혀 있습니다
- 겹칠 때 무엇을 해야 하는지 두 자리에서 말합니다

**나쁜 점**

- **오타로 만든 확정된 앱은 여전히 못 지웁니다.** 번들 ID 는 바꿀 수 없으므로 그
  앱은 영영 쓸모없는 채로 목록에 남습니다. 흔한 일은 아니지만 일어나면 방법이 없습니다
- **스토리지 삭제가 실패해도 등록은 지웁니다.** 오브젝트가 남을 수 있고, 그때는 로그가
  유일한 단서입니다. 반대로 하면 스토리지가 잠깐 맛이 간 동안 등록을 못 치웁니다
- 확인 팝업은 스크립트가 있어야 뜹니다. 없으면 바로 지워집니다. 권한과 상태는 서버가
  다시 보지만, **"정말?" 은 브라우저에만 있습니다**
- 등록 화면의 안내가 확인 중인 등록이 있을 때마다 나옵니다. 다른 앱을 올리는 중이면
  상관없는 말이고, 그 판단은 사람이 해야 합니다
