# ADR-0083: 서명 시도를 현재와 지난 시도로 나눠 보여준다

- 상태: 수락됨
- 날짜: 2026-11-05

## 맥락

한 버전을 여러 번 서명 시도하면, 관리 화면에 "서명 중" 배지와 직전 실패의 제목·
로그가 함께 떴습니다. 지금 어느 단계인지, 성공했는지 실패했는지 화면만으로는
판단할 수 없었습니다 (이슈 #85). 실제로 0.21.0 출시 때 서명이 열 번 넘게 재시도되는
동안, "다시 시도" 를 눌러도 직전 실패 메시지가 그대로 남아 상태가 섞여 보였습니다.

원인은 보고를 **버전당 하나로 접은 것**이었습니다. `SigningJob.latestReport` 는 한
버전의 여러 잡을 시도순으로 읽어, 내용이 있는 가장 최근 보고 하나만 남겼습니다.
다시 올려 새 잡이 생긴 순간 그 잡에는 아직 보고가 없어서, 접는 쪽은 **앞선 실패를
그대로 둔다** 를 골랐습니다. 화면과 `signing_status` 가 "실패한 적 없음" 으로 어긋나지
않게 하려던 것입니다 (ADR-0023 의 후속 구현).

그 선택에는 이유가 있었습니다. 접지 않고 "가장 최근 잡" 을 그냥 집으면, 재시도
직후의 빈 잡이 앞선 실패 갈래를 nil 로 지워서 화면이 실패를 놓쳤습니다. 하지만
그 대가로 **재시도 중에는 늘 직전 실패가 현재처럼 떴습니다.** 재시도가 잦을수록
과거와 현재가 포개져 사람이 상태를 오판했습니다.

데이터는 이미 시도별로 남아 있었습니다. 수동 재시도는 `SigningJob` 행을 새로 만들고
(ADR-0018 과 같은 1:N 구조), 각 행이 자기 `attempt`·`log`·`failure_code` 를 들고
있습니다. 묻혀 있던 것은 데이터가 아니라 **표시**였습니다.

## 결정

**보고를 접지 않고 시도별로 끊어, 현재 시도와 지난 시도를 나눠 보여줍니다.**

- 한 버전의 모든 잡을 생성 순서로 읽어 `1..N` 번호를 매긴다 (`SigningJob.attempts`).
  마지막이 현재 시도다.
- **현재 시도만 현재로 보여준다.** 버전 줄의 배지·로그·실패 블록은 마지막 잡에서
  온다. 재시도로 생긴 빈 잡이 현재면 실패 블록은 뜨지 않고 진행 상태만 보인다.
- **끝난 실패만 실패로 그린다.** 버전이 실제로 `failed` 일 때만 현재를 실패로 보여,
  자동 재시도(ADR-0018)로 큐에 돌아간 잡에 남은 갈래가 현재처럼 뜨지 않게 한다.
- **지난 시도는 "N번째 시도" 로 접어 둔다.** 펴면 그때의 상태·로그·실패 갈래·안내를
  본다. 최근 것이 위로 온다.
- 화면과 `signing_status` MCP 가 같은 모델을 쓴다. MCP 는 맨 위에 현재 시도를,
  `attempts` 배열에 시간순으로 전부 싣는다. 로그 전문은 싣지 않는다(상위 DTO 와 같은
  이유).

번호는 잡의 `attempt` 필드가 아니라 **생성 순서**로 매긴다. 자동 재시도는 같은 잡
행 안에서 `attempt` 를 올리므로, 그 값을 쓰면 번호가 띈다. 한 잡 행 = 사람이 한 번
누른 시도 하나(그 안의 자동 재시도 포함)로 보는 것이 화면과 맞다.

## 대안과 기각 사유

**접은 채로 두고 재시도 중에만 실패를 숨기기.** `latestReport` 는 그대로 두고,
버전이 `failed` 가 아니면 실패 블록만 감추는 작은 손질입니다. 데이터 조회가 그대로라
더 가볍고, 바꿀 코드도 적습니다. 그런데도 버린 이유는, 지난 시도를 들춰볼 길이
여전히 없어서입니다. 이슈가 요청한 "N번째 시도를 골라 보기" 를 못 하고, 접힌 하나
로는 열 번 재시도한 이력에서 무엇이 언제 어떻게 막혔는지 알 수 없습니다. 이번처럼
원인이 서명 머신 쪽에 있어 재시도가 잦은 상황이 바로 이력이 필요한 자리입니다.

**잡의 `attempt` 필드로 번호 매기기.** 저장된 값을 그대로 쓰면 조회가 단순합니다.
하지만 자동 재시도가 같은 잡 행 안에서 `attempt` 를 올리므로 번호가 띄고, 수동
재시도가 만든 새 행과 섞여 사람이 센 횟수와 어긋납니다. 생성 순서로 1..N 을 매기는
편이 화면과 맞아 그쪽을 택했습니다.

## 결과

**좋은 점.** 재시도 중에 현재 상태만 보여, 직전 실패가 현재처럼 섞이지 않습니다.
지난 시도를 "N번째 시도" 로 골라 그때의 로그·갈래·안내를 봅니다. 화면과
`signing_status` 가 한 모델을 써서 어긋나지 않습니다.

**나쁜 점.**

- **읽는 양이 는다.** 버전당 잡 하나가 아니라 전부를 읽는다. 재시도는 드물고 한
  버전의 잡 수는 작아 실무에서 문제는 아니지만, 접어 읽던 것보다는 무겁다. 목록
  화면은 여전히 한 번에 읽어(`attempts(ofVersions:)`) N+1 은 피한다.
- **번호가 내부 `attempt` 와 다를 수 있다.** 화면의 "3번째 시도" 가 잡의
  `attempt == 3` 과 항상 같지는 않다. 자동 재시도가 끼면 내부 카운터가 더 크다.
- **접힘이 지키던 불변식을 다른 방식으로 지킨다.** "화면과 API 가 같은 것을 본다"
  는 이제 접힘이 아니라 둘이 같은 시도 모델(`SigningJob.AttemptReport`)을 쓰는 것으로
  보장한다. 한쪽만 바꾸면 다시 어긋날 수 있어 둘을 그 모델로 묶어 둔다.

**후속 과제.** 자동 재시도(ADR-0018)는 아직 같은 잡 행에 로그를 누적한다. 그 안의
회차까지 시도로 나눠 보여줄지는 필요해지면 따로 정한다. 지금은 한 잡 행을 사람이
누른 시도 하나로 본다.
