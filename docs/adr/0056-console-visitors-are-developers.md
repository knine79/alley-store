# ADR-0056: 웹 콘솔로 들어온 사람은 개발자로 둔다

- 상태: 수락됨
- 날짜: 2026-09-21

## 맥락

베타 테스터에게 앱을 올려 달라고 하기 직전에 막혔습니다. 로그인한 사람은 `user` 로
만들어지는데 앱을 등록하려면 `developer` 여야 합니다. 그래서 순서가 이렇게 됩니다.

1. 테스터가 스토어에 들어와 로그인한다
2. 화면에 등록 버튼이 없다
3. 관리자를 찾아가 역할을 올려 달라고 한다
4. 관리자가 관리 > 사람에서 올린다
5. 테스터가 다시 들어온다

**3번이 문턱이 아니라 그냥 막힌 길이었습니다.** 사내 구성원이면 누구나 자기 앱을
올릴 수 있는 것이 이 스토어의 정책인데, 그 정책을 사람이 한 명씩 손으로 집행하고
있었습니다. 승인할 기준이 따로 없으니 관리자는 요청이 오면 올려줄 뿐입니다.

한편 `user` 라는 역할 자체는 필요합니다. 스토어 앱만 쓰는 사람이 있고, 그 사람에게
등록 권한을 줄 이유는 없습니다.

## 결정

**어디로 들어왔는지로 역할을 정합니다.**

| 들어온 곳 | 첫 역할 |
| --- | --- |
| 웹 콘솔 | `developer` |
| 스토어 앱 | `user` |

로그인 흐름은 이미 둘을 구분합니다. 스토어 앱은 `?client=app` 으로 인가를 시작하고,
그 값이 `OAuthStateToken.Target` 으로 콜백까지 따라옵니다 (ADR-0044 가 앱에 서버
주소를 박으면서 만든 길입니다).

이미 계정이 있는 사람도 웹 콘솔로 들어오면 `user` → `developer` 로 한 번 올립니다.
스토어 앱을 먼저 쓰다가 나중에 콘솔로 오는 사람이 그렇습니다.

**관리자가 손으로 정한 역할은 건드리지 않습니다.** `users.role_set_by_admin` 을 두고,
역할 화면에서 바꾸면 켭니다. 켜진 계정은 자동 승격이 건너뜁니다.

## 대안과 기각 사유

### 기본 역할을 그냥 `developer` 로 바꾼다

가장 적은 코드입니다. 마이그레이션도 판정도 필요 없고 한 줄이면 끝납니다.

기각합니다. 스토어 앱만 쓰는 사람까지 개발자가 됩니다. 전사 공개를 앞두고 있어
그쪽이 압도적으로 많아질 텐데, 역할 목록이 `developer` 로만 채워지면 그 칸이 아무
것도 구분하지 못하는 값이 됩니다. 나중에 "앱을 올린 적 있는 사람" 을 찾을 방법도
사라집니다.

### 역할을 없애고 등록을 모두에게 연다

정책이 "누구나 올릴 수 있다" 라면 역할이라는 칸 자체가 군더더기라는 주장입니다.
실제로 승인 기준이 없으니 일리가 있습니다.

기각합니다. 관리자와의 구분은 남아야 하고(스토어 설정·워커 등록·역할 관리),
`user` 는 스토어 앱 쪽에서 여전히 의미가 있습니다. 셋 중 하나만 없애자는 것인데,
없애면 되돌리기 어렵고 얻는 것은 판정 세 줄뿐입니다.

### 관리자가 도메인 규칙으로 미리 승격한다

허용 도메인으로 들어온 사람은 모두 `developer` 로 두자는 안입니다.

기각합니다. 허용 도메인은 이미 로그인 자체의 조건이라(`ALLOWED_EMAIL_DOMAINS`),
그 규칙을 한 번 더 쓰면 결국 "모두 `developer`" 와 같아집니다. 위 첫 번째 대안과
같은 문제입니다.

### 승격을 매 로그인마다 무조건 적용한다

`role_set_by_admin` 칸을 두지 않고, 웹으로 들어오면 언제나 `user` → `developer` 로
올리는 안입니다. 마이그레이션이 필요 없습니다.

기각합니다. 관리자가 누군가를 `user` 로 내려도 그 사람이 다음에 콘솔에 들어오면
되돌아갑니다. 역할 화면의 버튼이 눌리기는 하는데 아무것도 바꾸지 못하는 상태가
되고, 그것이 화면에 드러나지도 않습니다. 조용히 틀리는 종류라 칸 하나를 더
두기로 했습니다.

## 결과

### 좋은 점

- 베타 온보딩에서 사람이 끼어드는 단계가 사라집니다. 테스터는 들어와서 바로
  등록합니다
- 역할이 여전히 무언가를 구분합니다. `user` 는 "받기만 하는 사람" 입니다
- 관리자의 결정이 유지됩니다

### 나쁜 점

- **웹 콘솔 주소를 아는 것이 사실상의 권한이 됩니다.** 그 주소는 비밀이 아니므로,
  허용 도메인 안의 누구나 마음만 먹으면 개발자가 됩니다. 그것이 정책이라 받아들이는
  결정이지, 안전장치가 있어서 괜찮은 것이 아닙니다
- 칸이 하나 늘었습니다. `role_set_by_admin` 은 역할을 읽을 때 함께 봐야 하는 값인데,
  화면에는 나오지 않습니다. 관리자가 "왜 이 사람만 안 올라가지" 를 묻게 될 수 있습니다
- 기존 계정은 마이그레이션에서 전부 `role_set_by_admin = true` 로 채웁니다. 지금까지
  역할은 사람이 정하는 것 하나뿐이었으므로 그렇게 보는 것이 맞지만, **이미 `user` 인
  기존 계정은 자동 승격을 영영 받지 못합니다.** 필요하면 관리자가 한 번 올려줘야
  합니다

### 후속 과제

- 역할 화면에 "자동으로 정해진 역할인가" 를 드러낼지 검토합니다. 지금은 관리자가
  그 차이를 볼 방법이 없습니다
