## 지금 무엇을 먼저 하나

코드는 대부분 있고, **실제로 굴려본 적이 없는 것**이 남았습니다. 순서는 그 기준으로
정했습니다.

| | 무엇 | 왜 지금 |
| --- | --- | --- |
| 1 | 워커를 배포 서버에 붙여 실제 앱 한 바퀴 | 워커는 로컬 서버로만 시험했습니다. 서버와 워커 사이에서만 드러나는 것이 남아 있습니다 |
| 2 | [워커 자동 업데이트](#다음-워커-자동-업데이트---시작-전) | 워커 버그는 그 워커가 서명한 모든 앱에 영향을 줍니다. 지금은 고쳐도 퍼뜨릴 방법이 없습니다 |
| 3 | 워커 회귀 시험 (아래) | 2번의 승인 지점을 의미 있게 만듭니다 |
| 4 | Developer ID 프로필 발급 ([Phase 2](#phase-2-발급-자동화--cli-12주---대부분-완료)) | 실제로 프로필이 필요한 앱이 나올 때 |

**실제로 돌려봐야만 나오는 것들이 있습니다.** 실제 인증서로 서명을 돌려보다
프레임워크 안의 dylib 여섯 개가 서명에서 빠지는 것을 찾았고, 빈 디렉터리에서 서버를
띄워보다 설치 문서에 마이그레이션 단계가 통째로 빠진 것을 찾았습니다. 300KB 를
올리는 `curl` 에서 워커가 영구히 멈추는 것도 그렇게 나왔습니다. 셋 다 코드와
테스트로는 나오지 않았습니다. 그래서 아직 굴려보지 않은 조합이 맨 위에 옵니다.

### 워커 회귀 시험

워커 자동 업데이트에는 사람이 확인하는 지점이 필요한데, **승인 버튼만으로는 값이
거의 없습니다.** 위의 서명 버그가 그 증거입니다. `codesign --verify --deep --strict`
가 통과했는데 여섯 개가 미서명이었습니다. 화면에서 "승인" 을 눌러도 그것은 못 잡습니다.

기계가 검사하고 사람은 그 결과를 봐야 합니다.

- [ ] 중첩 프레임워크와 헬퍼가 있는 시험용 번들을 픽스처로 만든다
- [ ] 새 워커에게 그것을 서명시키고 결과를 서버가 검사한다 (서명 대상 수, 남은
      ad-hoc Mach-O 0개, 공증 통과, entitlements 가 `.app` 에만)
- [ ] 그 검사를 통과해야 승인할 수 있게 한다

실행 파일 하나짜리 번들로는 의미가 없습니다. 위의 버그를 잡으려면 프레임워크 안에
따로 서명해야 하는 코드가 들어 있어야 합니다.

그것도 함께 지웁니다. **이 값을 `S3_PRESIGNED_URL_TTL` 보다 짧게 두면 올리는 중인
파일의 자리를 지우게 됩니다.**

멀티파트 업로드는 넣지 않았습니다. 사내망에서 수백 MB를 올리는 상황이라 단순
재시도로 충분하다고 봤습니다. 근거와 대안은 ADR-0009에 있습니다.

- [x] signing_jobs 큐 + 워커 API (long-poll, 클레임, 하트비트)
- [x] 워커 토큰 발급·폐기 (API + 관리자 화면, [ADR-0013](adr/0013-worker-token-authentication.md))
- [x] codesign → notarytool → staple 파이프라인
- [x] entitlements 검사 (restricted 항목이 있는데 프로필이 없으면 서명 전 실패)
- [x] 업로더가 entitlements 를 함께 올린다 (API·CLI, `.app` 에만 적용,
      Electron JIT 검사, [ADR-0020](adr/0020-uploader-provides-entitlements.md)).
      웹 콘솔은 올릴 때 묻지 않고 실패한 자리에서 받는다
      ([ADR-0036](adr/0036-ask-for-entitlements-only-when-needed.md))
- [x] launchd 설치 스크립트 (`scripts/install-worker.sh`)
- [x] 워커 번들 조립·서명 (`scripts/build-worker-app.sh`, 스토어 앱과 공통 절차를 쓰는
      `scripts/lib/bundle.sh`, [ADR-0022](adr/0022-worker-as-signed-app-bundle.md))
- [x] 번들 설치 경로 (`install-worker.sh --bundle <zip>`, 워커 맥에 소스·Swift 불필요)
- [x] 실패 로그 수집/재시도
- [x] 멈춘 잡 회수: 하트비트가 끊긴 `running` 잡을 큐로 되돌리고, 시도 상한을 넘기면
      실패로 확정 ([ADR-0018](adr/0018-stalled-signing-job-recovery.md))
- [x] **실제 인증서로 E2E 검증** (로컬 서버 상대)
- [x] 올린 번들의 번들 ID 를 서명 전에 대조
      ([ADR-0029](adr/0029-verify-bundle-identifier-before-signing.md))
- [ ] 배포 서버 상대로 같은 루프 검증

**선행 조건**: 서명 워커를 돌릴 macOS 머신, Developer ID Application 인증서,
`notarytool store-credentials`로 저장한 공증 자격증명.

실제 Developer ID 로 미서명 앱을 끝까지 통과시켰습니다. 업로드 → 클레임 → 서명 →
공증(48초) → 티켓 첨부 → 결과 업로드 → `ready` 까지 갔고, 다시 내려받아
`source=Notarized Developer ID` 를 확인했습니다. 94개를 서명해야 하는 Electron 앱도
entitlements 세 개를 그대로 유지한 채 통과했습니다.

**상대는 로컬 서버였습니다.** 배포 서버에 붙였을 때만 드러나는 것 - presigned URL
수명, 잡 폴링의 네트워크 지연, 결과 업로드 경로 - 이 남아 있습니다.

실제로 돌려보고 잡은 것이 이 구간에서 셋 나왔습니다. 프레임워크 안의 dylib 여섯 개가
서명 대상에서 빠지던 것, `codesign --verify --deep --strict` 가 그 여섯 개를 통과시키던
것, 그리고 결과를 올리는 `curl` 에서 워커가 영구히 멈추던 것입니다. 마지막 것은
`Process.waitUntilExit()` 의 경합이었고, 워커가 잡 하나를 물고 멈춰서 그 뒤로 아무
잡도 받지 못했습니다. 셋 다 단위 테스트로는 나오지 않았습니다.

워커를 설치하려면 관리 > 서명 워커에서 토큰을 발급하고, 인증서가 있는 맥에서
`./scripts/build-worker-app.sh --sign` 으로 만든 **설치 키트**를 워커 맥으로 옮겨
`./install-worker.sh --config <설정 파일>` 을 실행합니다. 키트에는 번들과 설치
스크립트가 함께 들어 있고, 설정 파일 하나를 채우면 인증서 등록·공증 프로필 저장·
설치·환경 점검을 한 번에 합니다. 워커 맥에는 소스도 Swift 툴체인도 필요 없습니다.
절차와 빌드에 넘길 환경변수는 [설치 가이드](setup.md#4-서명-워커-설치)에 있습니다.

워커가 잡을 가져간 채로 죽으면 서버가 5분마다 훑어서 그 잡을 큐로 되돌립니다. 세 번
내보내고도 끝나지 않으면 실패로 확정합니다. 되돌린 사실은 관리 > 서명 워커의
"최근 서명 잡" 표에 시도 횟수로 나타납니다.

실제 Electron 앱으로 돌려보다 미서명 업로드에는 붙일 entitlements 가 없다는 것을
찾았습니다. 재서명이면 기존 서명에서 읽으면 되지만 미서명에는 읽을 것이 없어서, 권한이
빈 채로 Hardened Runtime 만 켜져서 서명됐습니다. 이제 업로더가 plist 를 함께 올립니다
([ADR-0020](adr/0020-uploader-provides-entitlements.md)). **빼먹으면 여전히 조용히
잘못된 앱이 나갑니다.** Electron 만 서명 전에 걸러냅니다.

콘솔은 빌드 스텝 없는 중립 CSS 한 장으로 만듭니다. 강조색과 로고는 스토어 설정에서
와서, 다른 조직이 띄우면 그 조직 것으로 보입니다. 사내용 고급 화면이 필요해지면
같은 API 에 붙는 별도 프론트엔드를 다른 레포에서 만듭니다.

브라우저에서 MinIO 로 직접 업로드하는 경로는 CORS 를 확인했습니다. MinIO 가
preflight 와 실제 `PUT` 양쪽에 헤더를 붙여줘서 [ADR-0009](adr/0009-presigned-artifact-transfer.md)
의 방식을 웹에서도 그대로 씁니다. 허용 출처는 `PUBLIC_BASE_URL` 로 좁혔습니다.

자바스크립트를 쓰는 화면은 둘입니다. 버전 업로드와 새 앱 등록입니다. 브라우저가
스토리지로 직접 올리면서 진행률을 보여주려면 폼 제출만으로는 안 됩니다
([ADR-0012](adr/0012-browser-upload-script.md)).

**새 앱 등록은 스크립트 없이도 등록까지는 됩니다.** 파일 칸이 감춰지고 폼이 그대로
`POST` 됩니다. 다만 첫 버전을 함께 올리는 것은 스크립트가 있어야 합니다
([ADR-0031](adr/0031-register-and-first-upload-in-one-screen.md)). 그 화면에서 할 수
있는 일이 스크립트 유무에 따라 달라지는 것은 ADR-0030 이 그은 경계가 흐려진
자리이고, ADR-0031 에 대가로 적어뒀습니다.

나머지 화면은 스크립트 없이 폼 `POST` 와 리다이렉트로 동작합니다.

**워커 등록 화면은 1-3 이후로 미룹니다.** `workers` 테이블이 아직 없습니다.
앱 멤버 추가·제거 화면과 콘솔에서의 다운로드도 아직 없습니다. 멤버는 API 로,
다운로드는 스토어 앱으로 합니다.

운영은 `docker-compose.yml` 과 `.env` 두 파일만 가져갑니다. 소스 없이 뜨는 것과
컨테이너 안에서 마이그레이션이 도는 것까지 로컬에서 확인했습니다. **레지스트리에서
실제로 받아본 것은 아직 아닙니다.** CI 를 한 번 돌려야 확인됩니다.

**스토리지 설정이 세 군데에서 배포 환경과 맞지 않았습니다.** 셋 다 첫 배포를 막는
문제였고, 환경변수 셋으로 풀었습니다. 배경과 대가는
[ADR-0024](adr/0024-storage-prefix-endpoints-credentials.md) 에 있습니다.

| 무엇이 문제였나 | 무엇을 더했나 |
| --- | --- |
| 버킷 루트에 쓴다. 프리픽스 하나만 소유하는 배포에서 막힌다 | `S3_KEY_PREFIX` |
| `S3_ENDPOINT` 가 서버가 붙는 주소이자 클라이언트에게 내주는 주소였다 | `S3_PUBLIC_ENDPOINT` |
| 액세스 키를 필수로 받는다. 역할로 인증하는 배포는 뜨지도 못한다 | 액세스 키를 선택으로 |

MinIO 로 확인했습니다. 프리픽스를 준 업로드가 `<프리픽스>/apps/...` 에 놓이는 것,
안 주면 예전 자리 그대로인 것, 내부·공개 주소를 다르게 준 presigned URL 이 실제로
통하는 것, 호스트만 어긋내면 403 이 나는 것, 액세스 키 없이 서버가 뜨는 것까지
직접 돌려봤습니다.

**presigned URL 수명은 아직 확인하지 못했습니다.** 임시 자격증명으로 서명하면
`S3_PRESIGNED_URL_TTL` 이 상한일 뿐이라는 것은 SDK 소스로 확인했지만, 실제 STS 환경에서
얼마나 사는지는 배포해봐야 압니다.

**배포까지는 됐습니다.** Kubernetes 샌드박스에 이미지를 올려 서버가 떴고
(`MIGRATE_ON_BOOT` + advisory lock 으로 스키마가 잡혔습니다), Google 로그인으로
첫 관리자가 만들어지고 허용 도메인 밖 계정이 거부되는 것까지 확인했습니다. 역할로
인증하는 스토리지(Pod Identity)에서 presigned URL 이 실제로 통하는 것도 확인했습니다.

**남은 것은 워커입니다.** 서명·공증·티켓 첨부 전체 루프는 **로컬 서버로만** 돌려봤습니다.
실제 인증서로 미서명 앱 하나를 끝까지 통과시켜 `source=Notarized Developer ID` 까지
확인했지만, 그 상대는 배포 서버가 아니었습니다. 워커를 배포 서버에 붙였을 때만
드러나는 것 - presigned URL 수명, 잡 폴링의 네트워크 지연, 결과 업로드 경로 - 이
남아 있습니다.

것이 API 연동보다 큰 일이라 실제로 필요한 앱이 나올 때 정합니다.

**App Store Connect 연동은 실제 키로 확인하지 못했습니다.** JWT 조립과 응답 해석,
만료 판단은 테스트로 확인했지만, Apple 이 그 토큰을 받아주는지는 키가 있어야 압니다.

## 운영 개선. 배포 전 보안 점검 반영 - 완료

사내 Kubernetes 샌드박스에 처음 올리기 전 플랫폼이 요구한 보안 점검에서 셋이
나왔습니다.

- [x] 피드 토큰을 질의 항목에서 경로 세그먼트로 옮기고, 옛 형식은 `Deprecation`
      헤더와 로그를 붙여 당분간 함께 받는다 ([ADR-0025](adr/0025-feed-token-in-path.md))
- [x] 보안 헤더 미들웨어를 스택 가장 바깥에 둔다. CSP 는 템플릿을 읽고 맞춘다
      ([ADR-0026](adr/0026-security-headers.md))
- [x] `PUBLIC_BASE_URL` 스킴과 `JWT_SECRET` 길이를 기동 시점에 검사하고, 어긋나면
      뜨지 않는다 ([ADR-0027](adr/0027-fail-fast-on-unsafe-config.md))

**셋 중 첫째는 문제를 없애지 못합니다.** 그 플랫폼의 액세스 로거는 경로와
쿼리스트링을 한 필드에 함께 적습니다. 토큰을 경로로 옮겨도 로그에서 사라지지
않습니다. 그 환경에서 실제로 기대는 것은 토큰이 읽기 전용이고 앱 하나에 묶여 있다는
것, 폐기가 즉시 반영된다는 것, 그리고 로그를 읽을 수 있는 사람을 좁게 두는 것입니다.
자세한 것은 ADR-0025 의 "나쁜 점" 에 적었습니다.

**동작이 둘 바뀝니다.** `JWT_SECRET` 이 32 바이트보다 짧으면 서버가 뜨지 않습니다.
`PUBLIC_BASE_URL` 이 loopback 이 아닌 http 여도 뜨지 않습니다. 기존 배포를 올릴 때
여기서 걸릴 수 있고, `JWT_SECRET` 을 바꾸면 이미 로그인한 사람이 전부 다시
로그인해야 합니다.

끊깁니다. 공증은 Apple 응답을 기다리는 구간이 길어서 그럴 확률이 낮지 않습니다.

**뜬 뒤 일정 시간 안에 하트비트를 못 보내면 스스로 이전 버전으로 되돌립니다.**
갈아끼운 워커가 뜨지 못하면 되돌릴 사람이 그 맥에 직접 가야 하는데, 그 맥은 원래
사람이 잘 가지 않는 머신입니다. 되돌릴 자리는 이미 있습니다. 설치 경로가 고정된
번들이라 이전 것을 옆에 두면 됩니다.

**사람이 확인하는 지점이 필요합니다.** 새 워커 번들을 서명하는 것이 지금 돌고 있는
워커입니다. 워커가 자기 다음 버전을 서명하고 그것으로 자기를 갈아끼우는 순환이
생깁니다. 잘못된 빌드가 나가면 그것을 되돌릴 워커도 그 빌드입니다. 승인을 어디에 둘지는
릴리스를 누가 만드는지와 함께 정합니다.

## MVP 수용 기준

Phase 1을 완료로 판정하는 조건 일곱 가지입니다. 그중 **3, 4, 7 은 실제 인증서와 OAuth
클라이언트가 갖춰진 뒤에야 확인할 수 있습니다.** 나머지는 코드와 테스트로
확인했습니다.

1. `docker compose up`만으로 로컬에서 서버·DB·스토리지가 뜨고 브라우저에서
   로그인까지 동작한다
2. 허용 도메인 밖의 계정은 로그인이 서버 단에서 거부된다
3. developer가 미서명 빌드를 올리면 워커가 자동으로 서명·공증·스테이플을 수행하고
   상태가 `ready`가 된다
4. released 버전을 스토어 앱에서 로그인 후 다운로드하면 Gatekeeper 경고 없이
   실행된다
5. 다운로드 이력에 사용자·버전·시각이 기록된다
6. 코드에 조직 고유 명사가 검색되지 않는다 (CI deny list 통과)
7. 스토어 앱은 서버 주소만 입력하면 다른 조직 서버에도 그대로 붙는다

## 검증 방법

- **단위 테스트**: 상태 머신 전이, 번들 ID 검증, 설정 로딩, 권한 미들웨어,
  OAuth 도메인 검증
- **통합 테스트**: docker-compose 기반 API 시나리오
  (등록 → 업로드 → 잡 생성 → 상태 전이)
- **E2E**: 파일럿 앱 1개로 실제 서명·공증·다운로드·Gatekeeper 통과 확인
- **보안 점검**: 워커 토큰 없는 잡 API 접근 거부, 비로그인 다운로드 거부,
  presigned URL 만료 확인, 메타 응답에 비밀값 미포함

## 정해진 것

| 항목 | 정한 것 |
| --- | --- |
| Sparkle 경로 허용 여부 | **허용합니다.** 앱이 스토어 앱 없이도 자체 업데이트합니다. 대신 appcast 경로로 받은 것은 사용자 단위 다운로드 이력이 남지 않습니다 ([ADR-0006](adr/0006-dual-path-app-updates.md)). Phase 4 에서 구현합니다 |
| 마이그레이션 실행 시점 | **기본은 사람이 `migrate` 를 돌립니다.** 그 명령을 실행할 수단이 없는 플랫폼을 위해 `MIGRATE_ON_BOOT` 를 열었습니다. 켜면 기동하면서 돌고, 여러 대가 동시에 도는 문제는 Postgres advisory lock 으로 막습니다 ([ADR-0028](adr/0028-migrate-on-boot-with-advisory-lock.md)) |

## 열려 있는 결정

착수 전에 정해야 하는 것들입니다.

| 항목 | 정해야 할 시점 | 내용 |
| --- | --- | --- |
| 재개 가능 업로드 | 실패가 잦아지면 | MVP는 단순 재시도로 간다. 대용량에서 실패가 잦으면 멀티파트로 확장한다 ([ADR-0009](adr/0009-presigned-artifact-transfer.md)) |
| 웹 콘솔 SPA 전환 | 통계·피드백 화면이 복잡해지면 | Leaf 서버 렌더링으로 시작한다. 통계·피드백 대시보드가 복잡해지면 재검토한다. 사내용 고급 화면이 먼저 필요해지면 같은 API 에 붙는 별도 프론트엔드를 다른 레포에서 만든다 |
| 설치 완료 보고 | 통계가 부족해지면 | 지금 통계는 "받아갔다"까지다. 스토어 앱이 설치 성공을 따로 보고하면 설치 수를 셀 수 있지만, 그 값이 큰지 아직 모른다 |
| 앱 단위 기본 entitlements | 같은 파일을 매번 첨부하는 것이 번거로워지면 | 지금은 버전마다 함께 올린다. 앱에 기본값을 두면 편하지만 바이너리와 권한이 따로 놀 수 있다 ([ADR-0020](adr/0020-uploader-provides-entitlements.md)) |
| 서버 이미지 멀티아키텍처 | arm 호스트에 올려야 할 때 | 지금은 linux/amd64 만 발행한다. QEMU 크로스빌드는 Swift 빌드에서 값이 너무 크고, 네이티브 arm 러너는 공개 레포에서만 무료다. 필요해지면 러너 매트릭스로 붙인다 ([ADR-0021](adr/0021-publish-server-container-image.md)) |
| 이미지 보관 정책 | 저장 용량이 문제가 될 때 | 커밋마다 sha 태그가 쌓이는데 지우는 규칙이 없다 ([ADR-0021](adr/0021-publish-server-container-image.md)) |
| 워커 설치 시 Team ID 확인 | 워커를 여러 조직이 쓰게 되면 | 설치 스크립트가 번들의 서명은 확인하지만 어느 팀이 서명했는지는 보지 않는다. 확인하려면 조직마다 다른 Team ID 를 환경변수로 받아야 하고, 안 넣은 사람에게는 아무 보호가 없다 ([ADR-0022](adr/0022-worker-as-signed-app-bundle.md)) |
| Electron 밖의 JIT 런타임 검사 | 그런 앱이 실제로 깨지면 | 지금 검사는 Electron Framework 하나만 본다. JVM·Mono 는 잡지 못한다. 일반화하려면 번들 안의 바이너리가 무엇을 링크했는지 봐야 한다 |
| 옛 피드 주소(`?token=`)를 언제 없앨지 | 옛 형식 요청이 그친 뒤 | 이미 배포된 앱의 `SUFeedURL` 에 옛 형식이 박혀 있을 수 있어 지금은 함께 받는다. 판단 근거는 `폐기 예정인 질의 형식 피드 주소 사용` 로그다. 날짜를 먼저 박으면 그날 무엇이 깨지는지 모르는 채로 지우게 된다 ([ADR-0025](adr/0025-feed-token-in-path.md)) |
| CSP 위반 보고 수집 | 화면이 CSP 로 깨지는 일이 잦아지면 | 지금은 위반이 브라우저 콘솔에만 남아 서버가 알지 못한다. `report-to` 를 붙이려면 보고를 받을 자리를 먼저 만들어야 한다 ([ADR-0026](adr/0026-security-headers.md)) |
| 주기적 훑기를 한 인스턴스만 돌게 잠글지 | 서버를 실제로 여러 대로 늘릴 때 | 잠금 장치는 부팅 시 마이그레이션에 쓰려고 이미 만들었다(`AdvisoryLock`). 훑기를 감싸는 것만 남았는데, 한 대인 지금은 걸릴 일이 없어 미뤄뒀다 ([ADR-0018](adr/0018-stalled-signing-job-recovery.md), [ADR-0028](adr/0028-migrate-on-boot-with-advisory-lock.md)) |
